# ADR-DES.STACK.framework-vs-vs

**Статус:** ПРИНЯТО
**Дата:** 2026-08-02
**Контекст:** Выбор фреймворков для VEDO EduTrack (M0.1, T3)

Язык зафиксирован в `ADR-DES.STACK.language-vs-vs` (ПРИНЯТО): **Go** (бэкенд) + **TypeScript** (фронтенд). Стиль — модульный монолит (`ADR-DES.INFRA.modular-monolith-approach`): 10 модулей Clean Architecture в одном процессе. Продукт — веб-приложение клиент-сервер (`REQ-NFR-infra.compliance.client-server-web-app`): фронт — тяжёлая SPA-визуализация (карта знаний F4.1, конструктор маршрутов F4.3, дашборды), бэкенд — REST/SPARQL/webhooks/MCP + CLI-интерфейс единого бинарника (`ADR-DES.API.cli-interface`, 2026-08-03). Стратегия: вайбкодинг + компенсация тестированием и документацией. Внешние интеграторы — EdTech-платформы через REST API (F6.1).

**Ключевые драйверы:**
- OpenAPI как источник истины и документация API ≥ 90% эндпоинтов (`REQ-NFR-ops.compliance.user-documentation`)
- Визуализация — ядро UX (F4): графы, дашборды, node-редактор
- Тестирование: Vitest + React Testing Library / Playwright, покрытие API-контрактов (integration ≥ 70%) (`REQ-NFR-process.dev.test-coverage`)
- i18n: react-i18next на фронте, ICU (`REQ-NFR-ops.compliance.i18n-readiness`)
- WCAG 2.1 AA, axe-core = 0 critical (`REQ-NFR-ui.compliance.wcag-level`)
- Стилизация — дизайн-токены (темы light/dark), синхронизация «дизайн (pen.dev) ↔ код» (`ADR-DES.PROCESS.pencil-design-adoption`)
- Фронтенд-тулчейн — Vite (бандлер/dev-server), Vitest (тесты), pnpm (пакетный менеджер, монорепо): скорость сборки, единый раннер тестов, воспроизводимость зависимостей

**Требование-источник:**
- `REQ-NFR-ops.compliance.user-documentation`
- `REQ-NFR-process.dev.test-coverage`
- `REQ-NFR-ops.compliance.i18n-readiness`
- `REQ-NFR-ui.compliance.wcag-level`
- `REQ-NFR-infra.compliance.client-server-web-app`
- `REQ-NFR-security.compliance.owasp-application-security`

**Решение:**

Принять:
- **Бэкенд-фреймворк: `chi`** (Go) — лёгкий, идиоматичный, stdlib-совместимый.
- **API-слой: `oapi-codegen`** — генерация серверных стабов из OpenAPI-спеки (контракт → код).
- **CLI-фреймворк: `cobra`** (Go) — дерево подкоманд единого бинарника `vedo-edutrack` (server / mcp / migrate / seed / ontology sync / route compute / plan get / gap diagnose / report) — `ADR-DES.API.cli-interface`.
- **Фронтенд: React + TypeScript** с React Flow (конструктор) + Cytoscape.js (карта знаний, canvas).
- **Типизированный клиент фронта: `openapi-typescript`** — из той же спеки.
- **Стилизация фронта: Tailwind CSS** — utility-first, дизайн-токены как CSS-переменные (`@theme`, темы light/dark), синергия с pen.dev (Pencil) и вайбкодингом.
- **Бандлер/dev-server фронта: `Vite`** — стандартный инструмент React SPA: instant dev-server + HMR, быстрая production-сборка; fit с `make dev` (Vite dev для React).
- **Тестирование фронта: `Vitest`** — единый раннер unit/компонентных тестов (React Testing Library), Vite-нативный (общий конфиг и трансформация TS/JSX), покрытие Domain/Application фронта без браузера.
- **Пакетный менеджер: `pnpm`** — быстрее и экономнее npm (content-addressable store, симлинки), строгая изоляция зависимостей, монорепо-воркспейс (Go + React в одном репо, единый lockfile `pnpm-lock.yaml`).

**Аргументы за chi (бэкенд):**

| # | Аргумент | Обоснование |
|---|----------|-------------|
| 1 | Идиоматичность | chi построен на `net/http` (stdlib) — без магии; middleware-цепочки чистые; идеален для модулей Clean Architecture |
| 2 | Границы монолита | Минимальный фреймворк не навязывает структуру — модули (bounded contexts) сами определяют свои роуты; арх-линтеры (depguard) контролируют зависимости |
| 3 | Вайбкодинг | Минимум API-поверхности = стабильная AI-генерация; меньше «волшебных» конструкций, которые AI может сгенерировать неверно |
| 4 | Совместимость | `otelhttp`-middleware, rate limiting, graceful shutdown — стандартные паттерны net/http |

**Аргументы за oapi-codegen (OpenAPI-first):**

```
OpenAPI-спек (источник истины, в репозитории)
   ├── oapi-codegen        → типизированные серверные стабы (Go)
   ├── openapi-typescript  → типизированный клиент (React)
   ├── swagger-ui          → живая документация (NFR: ≥ 90% эндпоинтов)
   └── контрактные тесты   → дрейф спеки/кода = CI-ошибка
```

- **Документация — наша стратегия компенсации:** OpenAPI генерирует и документацию, и код, и контрактные тесты из одного источника. Изменение API = перегенерация + тесты ловят дрейф — «ручной синхронизации типов» нет, это автоматизировано.
- **Отклонение tRPC:** tRPC работает только TypeScript-на-TypeScript (клиент И сервер на TS) — с Go-бэкендом физически неприменим.
- **Отклонение Connect (gRPC-web):** возможен Go↔TS, но NFR требует REST API (F6.1) для внешних EdTech-интеграторов, SPARQL, webhooks — всё REST-экосистема; OpenAPI — требование документации.

**Аргументы за cobra (CLI):**

| # | Аргумент | Обоснование |
|---|----------|-------------|
| 1 | Стандарт Go-монолитов | Де-факто стандарт CLI для крупных Go-проектов (kubectl, docker, gh, helm): предсказуемое дерево команд, зрелый help/completion, отлажен на больших масштабах |
| 2 | MCP stdio (`REQ-FR-api.mcp.server`) | AI-клиенты спавнят бинарник как subprocess — cobra даёт spawnable-подкоманду `mcp` из коробки (тот же паттерн, что отдельный бинарник) |
| 3 | Вайбкодинг | Огромный AI-корпус команд cobra; декларативная структура `Use/Short/RunE` — стабильная генерация; команды тонкие, логика — в use cases модулей |
| 4 | Единый артефакт | Один бинарник для сервера и инструментов (`server` + migrate/seed/…) — поставка on-prem (Go embed) и тулинг в контейнере без второго артефакта |
| 5 | Скриптуемость | Без интерактивных промптов, `--output json|table|csv`, `--yes` — cron/CI/Kubernetes Job дружелюбен; help/completion бесплатны |
| 6 | Совместимость | Стандартные паттерны `flag`/`pflag`; интеграция с wire (per-command lazy wire) не требует особых механизмов |

**Аргументы за React (фронтенд):**

| # | Аргумент | Обоснование |
|---|----------|-------------|
| 1 | Вайбкодинг: AI-корпус | JSX/React — самый представленный UI-паттерн в обучающих данных; стабильная генерация, меньше галлюцинаций |
| 2 | Визуализация (F4 — ядро UX) | React Flow (node-редактор) + Cytoscape.js (canvas-граф, >500 нод, Web Workers для layout) — зрелые, типизированные |
| 3 | Тестирование | React Testing Library — индустриальный стандарт (тестируй как пользователь); Playwright для e2e |
| 4 | i18n | react-i18next — лучший в классе, ICU, 0-code добавление языка (NFR) |
| 5 | Экосистема | Крупнейшая: состояние (Zustand), типизация, a11y-ресурсы |

**Аргументы за Tailwind CSS (стилизация):**

| # | Аргумент | Обоснование |
|---|----------|-------------|
| 1 | Вайбкодинг: AI-корпус | Tailwind — доминирующий подход к стилизации в AI-генерации (shadcn/ui, современные React-стеки); утилиты детерминированы, генерация стабильна |
| 2 | Дизайн-токены ↔ CSS-переменные | Tailwind v4: токены как CSS-переменные (`@theme`) — прямая синхронизация с переменными pen.dev (Pencil) и темами light/dark без препроцессора |
| 3 | Границы Clean Architecture | Утилиты — декларативный слой представления; не протекают в Domain/Application; компоненты React + Tailwind — внешний круг (Frameworks) |
| 4 | a11y и i18n | Утилиты не мешают семантике (ARIA — в JSX), dark mode — variant `dark:`; не конфликтует с react-i18next |
| 5 | Экосистема | Крупнейшая в связке с React (shadcn/ui, headlessui, Tailwind UI); CSS Modules остаётся для точечных случаев |
| 6 | Производительность | JIT-компиляция, нулевой runtime JS, минимум CSS в бандле |

**Аргументы за фронтенд-тулчейн (Vite + Vitest + pnpm):**

| # | Аргумент | Обоснование |
|---|----------|-------------|
| 1 | Vite: скорость dev | Instant dev-server + HMR, быстрая production-сборка — стандарт React SPA; CRA устарел, Webpack медленный |
| 2 | Vite: вайбкодинг | Zero-config, минимум конфигов → стабильная AI-генерация; fit с Makefile (`make dev`, `make build`) |
| 3 | Vitest: единый раннер | Vite-нативный (общий конфиг, трансформация TS/JSX) — тесты без отдельного стенда; тот же API (describe/expect), что и Jest |
| 4 | Vitest: покрытие ядра фронта | Unit/компонентные тесты Domain/Application (чистые функции, сторы) ≥ 90% без браузера — стратегия «компенсация тестированием» (RTL + MSW) |
| 5 | pnpm: скорость и экономия | Content-addressable store, симлинки — быстрее и меньше диска, чем npm |
| 6 | pnpm: строгая изоляция | Нет «левых» peer-хоистов — детерминированные зависимости (важно для вайбкодинга и supply-chain) |
| 7 | pnpm: монорепо | Воркспейс (apps/*, tools/*): Go + React в одном репо, единый `pnpm-lock.yaml`, общая версия Node (`.nvmrc`) |

**Рассмотренные альтернативы:**

| Альтернатива | Оценка | Причина отклонения |
|--------------|--------|--------------------|
| **Gin / Echo (Go)** | ⚠️ | Gin — популярен, но больше магии/конвенций, менее идиоматичен для чистой архитектуры; Echo — «из коробки» чуть больше, но связывает с собственными абстракциями. chi — минимален и stdlib-совместим |
| **NestJS (TS-бэкенд)** | ❌ | Отклонён вместе с TS-бэкендом (языковой ADR): Node-runtime на on-prem, границы по конвенции; его сильные стороны (авто-OpenAPI, DI) компенсированы oapi-codegen + wire в Go |
| **Next.js (full-stack)** | ❌ | Фронт-центричный SSR-фреймворк; наша визуализация — тяжёлая SPA (canvas/WebGL) — SSR не нужен и вреден; бэкенд — доменный монолит, не Next-API-routes |
| **FastAPI (Python)** | ❌ | Отклонён с Python (языковой ADR) |
| **Spring Boot (Java)** | ❌ | Отклонён с Java (языковой ADR) |
| **Vue 3** | ⚠️ | Достойная альтернатива (проще вход, RU-документация, Pinia, vue-flow). Отклонена: меньше AI-корпус (вайбкодинг!), vue-flow — порт React Flow (следует за оригиналом), меньше готовых граф-компонентов, RTL-экосистема меньше |
| **tRPC** | ❌ | Только TS↔TS — неприменим с Go-бэкендом |
| **Connect (gRPC-web)** | ⚠️ | Технически возможен Go↔TS, но REST/OpenAPI требуются NFR (F6.1, документация) — вводить второй контракт без пользы |
| **stdlib `flag` / ручной парсинг (CLI)** | ⚠️ | Ноль зависимостей, но нет дерева подкоманд, help/completion, флагов `--output` из коробки — при 9 подкомандах это ручная работа; cobra — стандарт |
| **`urfave/cli` (CLI)** | ⚠️ | Хороший альтернативный фреймворк, но меньше AI-корпус и экосистема, чем у cobra; cobra — де-факто стандарт Go-монолитов |
| **`kong` (CLI)** | ⚠️ | Декларативный, элегантный; но выше порог вайбкодинга (структуры-теги, генерация из типов) и меньше корпус; cobra проще генерируется |
| **CSS Modules** | ⚠️ | Локальные стили без vendor-риска; но нет токенов/тем из коробки, больше бойлерплейта, слабее AI-корпус; остаётся опцией для точечных переопределений |
| **Styled Components / CSS-in-JS** | ❌ | Runtime-затраты (JS в бандле), сложнее гигиена SSR, слабее генерация у ИИ; конфликт с бюджетом p95 и простотой |
| **MUI (Material UI)** | ⚠️ | Готовые компоненты, но тяжёлый бандл и собственный дизайн-язык (конфликт с брендовой дизайн-системой); хуже кастомизация токенов |
| **Чистый CSS / Sass** | ⚠️ | Рабочий минимум; нет утилит и токенов — медленнее вайбкодинг, больше ручного кода |
| **Webpack / CRA (бандлер)** | ❌ | Медленная сборка, устаревший CRA; Vite — современный стандарт React-SPA, быстрее dev-server + HMR |
| **Jest (тесты фронта)** | ⚠️ | Мощный, но отдельный раннер: свой конфиг, трансформация, медленнее; Vitest — Vite-нативный, тот же API, быстрее. Jest остаётся опцией для специфичных снапшотов |
| **npm / yarn (пакетный менеджер)** | ⚠️ | npm — медленнее и больше диска; yarn classic устарел; pnpm — быстрее, экономнее, строгая изоляция, воркспейс |

**Последствия:**

*Положительные:*
- OpenAPI-first: один источник истины (документация + код + тесты) — стратегия «компенсация документацией» выполнена системно.
- CLI (cobra): единый бинарник `vedo-edutrack` — сервер и инструменты (migrate/seed/route compute/…) в одном артефакте; MCP stdio (F6.6) реализуется как подкоманда; тулинг воспроизводим в контейнере и скриптуем (cron/CI).
- Визуализация: Cytoscape (карта/лакуны) + React Flow (конструктор) — правильные инструменты под разные задачи; Web Workers для layout больших графов.
- Вайбкодинг: React (макс. корпус) + chi (минимальный API) — надёжная генерация.
- Стилизация: Tailwind + дизайн-токены (CSS-переменные) — единый контур «дизайн (pen.dev) ↔ код», темы light/dark без препроцессора.
- Фронтенд-тулчейн: Vite (быстрая сборка/HMR) + Vitest (единый раннер с покрытием ядра без браузера) + pnpm (монорепо, скорость, изоляция) — стратегия «компенсация тестированием и документацией» поддержана нативно.

*Отрицательные и смягчение:*
- cobra: новая зависимость и размер бинарника → команды подключаются по мере готовности модулей (lazy wire), `-ldflags="-s -w"`; Apache-2.0 без конфликтов (проверка лицензий в CI, supply-chain NFR); CLI — доверенный операторский инструмент (аудит-логи, `ops-admin-separation`).
- oapi-codegen: генерация требует дисциплины ведения спеки → спека в репозитории, контрактные тесты в CI (дрейф = ошибка).
- Два языка/фреймворка (Go + React) → общий контракт OpenAPI, разделение обязанностей чёткое.
- React: рендеринг больших графов через React-дерево → Cytoscape (canvas вне React-рендеринга) + Web Workers — именно поэтому выбраны оба инструмента.
- chi: меньше «из коробки» (валидация, guards) → oapi-codegen + wire + middleware-цепочки (rate limiting, auth) — стандартные паттерны.
- Tailwind: утилиты в JSX раздувают разметку → токены в `@theme`, кастомные классы только для переиспользуемых паттернов; контроль на ревью и линтерами (engineering-gates).
- Vitest менее зрел, чем Jest (экосистема моков/снапшотов) → смягчение: RTL + MSW (mock service worker) — зрелые инструменты; Jest остаётся опцией для специфичных случаев.
- pnpm: строгая изоляция требует дисциплины peer-зависимостей → смягчение: явные devDependencies, контроль postinstall через `onlyBuiltDependencies` (supply-chain NFR).
