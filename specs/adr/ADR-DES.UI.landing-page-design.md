# ADR-DES.UI.landing-page-design

**Статус:** ПРЕДЛОЖЕНО
**Дата:** 2026-08-03
**Контекст:** Дизайн публичной посадочной страницы (M0.3, T14 — «Build landing page»)

EduTrack — сервис образовательных маршрутов на базе VEDO Hub; фронтенд — React + TypeScript SPA (T3), визуализация — React Flow + Cytoscape.js, стилизация — Tailwind CSS v4 + дизайн-токены (`ADR-DES.PROCESS.pencil-design-adoption`, `ADR-DES.STACK.framework-vs-vs`). Внутренняя структура — Clean Architecture (`ADR-DES.INFRA.clean-architecture-adoption`): UI — периферия (Interface Adapters/Frameworks), бизнес-правила не живут в компонентах.

Функциональное требование посадочной страницы зафиксировано (`REQ-FR-onboarding.landing.explore-value-proposition`, P1): публичная страница (`/`) без авторизации сообщает ценностное предложение, содержит hero, три карточки ценностных предложений, CTA «Sign In» (→ `/login`) и «Learn More» (якорь к секции возможностей), футер; маршрутизирует посетителя к входу/регистрации (roadmap M0.3: «Landing page communicates the product value proposition and routes users toward registration»); локали RU + EN (`REQ-NFR-ops.compliance.i18n-readiness`); доступность WCAG 2.1 AA (`REQ-NFR-ui.compliance.wcag-level`).

Дизайн страницы до сих пор не зафиксирован: нет решения о структуре секций, компоновке, компонентной модели, поведении при авторизованном пользователе, обработке локалей и тёмной темы. Это первый публичный экран продукта — он формирует первое впечатление и воронку регистрации (B2C-трек «Дай пять», G3 — снизить порог входа), поэтому дизайн-решение фиксируется ADR, а не оставляется на усмотрение реализации.

**Ключевые драйверы:**
- **Первое впечатление и воронка**: страница — точка входа в продукт; цель — передать ценностное предложение за ≤ 5 секунд сканирования и направить к CTA («Sign In»), не отвлекая (G3, `REQ-FR-onboarding.landing.explore-value-proposition`).
- **Вайбкодинг и дизайн как код**: структура страницы описывается декларативно (секции → компоненты → токены), воспроизводима ИИ-ассистентами и командой (`ADR-DES.PROCESS.pencil-design-adoption`, `REQ-NFR-process.dev.developer-documentation`).
- **i18n RU+EN**: все строки — в файлах переводов (react-i18next, ICU); макеты не содержат хардкода (`REQ-NFR-ops.compliance.i18n-readiness`).
- **WCAG 2.1 AA**: контраст, семантика, клавиатура, screen reader — с первого коммита, не пост-фактум (`REQ-NFR-ui.compliance.wcag-level`, `REQ-FR-a11y.navigation.dashboards-keyboard` — паттерн распространяется на публичные страницы).
- **Темы light/dark**: токены из дизайн-системы; лендинг — первый кандидат на проверку темизации (`ADR-DES.PROCESS.pencil-design-adoption`).
- **Перформанс и SEO-нейтральность**: публичная страница отдаётся из SPA-бандла (M0.3 — embedded SPA в едином бинарнике, `ADR-DES.INFRA.docker-images-environments`); тяжёлая визуализация (Cytoscape/React Flow) на лендинг не грузится — ленивый импорт (`React.lazy`).
- **Авторизованный пользователь**: `/` для авторизованного — редирект на ролевой дашборд (`/dashboard`), не показ маркетингового экрана (ProtectedRoute).

**Требование-источник:**
- `REQ-FR-onboarding.landing.explore-value-proposition` (P1) — функциональное требование посадочной страницы
- `REQ-NFR-ops.compliance.i18n-readiness` — локали RU + EN, ICU, fallback на русский
- `REQ-NFR-ui.compliance.wcag-level` — доступность WCAG 2.1 AA
- `REQ-NFR-infra.compliance.client-server-web-app` — веб-приложение, клиент-сервер
- `REQ-NFR-ops.observability.product-metrics` — метрики воронки (переход с лендинга на `/login`)
- `REQ-NFR-process.dev.engineering-gates` — компоненты обязаны проходить те же гейты (линтеры, тесты, a11y-аудит)

**Решение:**

Принять дизайн посадочной страницы как **одностраничный маркетинговый лендинг (single-page marketing landing)** с линейной вертикальной компоновкой секций, лёгкой визуальной иерархией «hero → ценностные предложения → CTA», без внешних ссылок на тяжёлый контент и без встроенной графики знаний на первом экране.

1. **Структура секций (сверху вниз)**: шапка (логотип + навигация + CTA «Sign In») → hero (заголовок + слоган + CTA «Sign In»/«Learn More») → 3 карточки ценностных предложений (Knowledge Graph Routes / Progress Tracking / Gap Diagnosis) → секция возможностей (якорь «Learn More», детализация фич с мини-иллюстрациями) → футер (копирайт, ссылки, переключатель языка RU/EN).

2. **Компонентная модель** (`frontend/src/pages/Landing.tsx` + `frontend/src/features/landing/`): секции — самостоятельные компоненты (`LandingHeader`, `LandingHero`, `ValuePropsCard`, `LandingFeatures`, `LandingFooter`); переиспользуемые примитивы — из shared-слоя (`Button`, `Card`, `Badge`); строки — через `useTranslation` (react-i18next), 0 захардкоженных строк.

3. **Маршрутизация**: `/` → `LandingPage` (public, без авторизации); `ProtectedRoute` перенаправляет авторизованного на `/dashboard`; CTA «Sign In» — навигация на `/login`; «Learn More» — якорь `#features` (секция возможностей).

4. **Визуализация не грузится на лендинг**: Cytoscape.js/React Flow подключаются лениво только на страницах карты знаний/конструктора (`React.lazy` + `Suspense`); бандл лендинга остаётся лёгким (без тяжёлой графики на критическом пути).

5. **Токены и темы**: все цвета/типографика/отступы — из дизайн-токенов (CSS-переменные, `@theme`); поддержка light/dark с первого релиза; контраст текста на фоне — по WCAG 2.1 AA.

6. **i18n**: `i18n`-ресурсы `ru`/`en` (react-i18next, ICU); переключатель языка — в шапке/футере; fallback — русский (`language.ui: ru`).

7. **a11y**: семантическая разметка (header/nav/main/section/footer, один `h1`), видимый фокус, aria-атрибуты для CTA и навигации, скринридер-описания для карточек.

8. **Метрики воронки**: событие `landing.cta_clicked` (атрибут CTA) на клик «Sign In» — вход для product-metrics (доля посетителей, дошедших до входа).

**Рассмотренные альтернативы:**

| Альтернатива | Оценка | Причина отклонения |
|--------------|--------|--------------------|
| **Dashboard-first (после входа сразу в продукт, без маркетингового экрана)** | ⚠️ | Правильно для возвращающихся/авторизованных (редирект `/` → `/dashboard`), но не решает задачу привлечения: неавторизованный посетитель не получает ценностное предложение и путь к регистрации; оставлено как поведение для авторизованных (A2 в UC) |
| **Лендинг с встроенной картой знаний (Cytoscape на первом экране)** | ❌ | Тяжёлая визуализация на критическом пути: рост бандла/TTI, отвлекает от CTA; граф знаний — продуктовая фича для авторизованных (F4.1), её место — в дашборде, не на маркетинговом экране; мини-иллюстрации фич — лёгкие статичные изображения |
| **Многостраничный маркетинговый сайт (отдельные страницы Features/Pricing/Docs)** | ⚠️ | Избыточен для MVP/M0.3: одна секция «Features» закрывает задачу «Learn More»; разделение страниц добавит маршруты, контент и накладные расходы на i18n без требований; пост-MVP при необходимости — расширение лендинга |
| **Одноэкранный hero без секций (только заголовок + CTA)** | ⚠️ | Максимально короткий путь к CTA, но не передаёт 3 ценностных предложения (требование FR); критерий приёмки «3 карточки» нарушается |
| **Лендинг как статичный HTML вне SPA** | ❌ | Конфликтует с M0.3 (embedded SPA в едином бинарнике, `ADR-DES.INFRA.docker-images-environments`): две точки раздачи публичного контента, дублирование шапки/футера, разрыв i18n и дизайн-токенов |

**Последствия:**

*Положительные:*
- **Ценностное предложение за ≤ 5 секунд**: hero + 3 карточки + CTA на одном экране; прямое выполнение критериев приёмки FR (3 карточки, CTA → `/login`, якорь `#features`).
- **Лёгкий бандл лендинга**: без Cytoscape/React Flow на критическом пути — быстрый TTI для публичной страницы (первый экран продукта).
- **Воспроизводимость для вайбкодинга**: декларативная структура секций → компонентов → токенов; `.pen`-макет лендинга может быть сгенерирован/синхронизирован через Pencil (MCP), код — из структуры.
- **i18n и темы с первого коммита**: все строки в ресурсах, все стили — токены; RU+EN и light/dark не требуют переписывания страницы.
- **Единая воронка**: метрика `landing.cta_clicked` → `/login` измерима сразу (`REQ-NFR-ops.observability.product-metrics`).

*Отрицательные и смягчение:*
- **Маркетинговый контент — новая ответственность** (копирайтинг слогана, описания фич) → смягчение: контент в i18n-ресурсах, ревью текста в PR; копия hero — из FR/vision (слоган уже зафиксирован в требовании).
- **Одностраничность ограничивает расширение** (нет отдельного Pricing/Docs) → смягчение: структура секций модульная; добавление страницы пост-MVP — отдельный маршрут без изменения архитектуры лендинга.
- **Якорная навигация (#features) в SPA** требует обработки скролла и истории → смягчение: react-router + стандартный якорный скролл с учётом фиксированной шапки (scroll-margin); тест навигации в E2E.
- **Риск хардкода строк/цветов** в компонентах → смягчение: гейты — i18next-scanner (0 захардкоженных строк, `REQ-NFR-ops.compliance.i18n-readiness`), арх-тесты на токены; a11y-аудит axe-core в CI (`REQ-NFR-ui.compliance.wcag-level`).
