### UC-api.webhooks.module-mastered: Уведомление о событии module.mastered

**Актор:** Система
**Приоритет:** P1
**Ключевая функция:** F6.4
**Канал:** Webhook
**Описание:** При освоении модуля система отправляет внешнему подписчику (EdTech-платформа, LMS, родительский сервис) webhook-событие `module.mastered`. Доставка идемпотентна: дублирование событий не ломает состояние подписчика и EduTrack.
**Основной поток:**
1. Триггер: событие освоения модуля подтверждено (проверочное задание F2.2 или ручное подтверждение).
2. Система фиксирует освоение в состоянии учащегося и запускает каскад пересчёта маршрута (F1.2, F1.6).
3. Система формирует payload события `module.mastered`: event_id (уникальный), learner_id, module_id, timestamp, версия маршрута, обновлённые горизонты (F1.3).
4. Система определяет подписчиков данного учащегося/платформы и отправляет событие на их webhook-URL с подписью (HMAC) для верификации.
5. Подписчик подтверждает приём (HTTP 2xx) — система помечает событие доставленным.
6. При недоставке система выполняет повторные попытки по расписанию с экспоненциальной задержкой и ограничением числа попыток.
7. Подписчик обрабатывает событие; при дубликате (повторная доставка того же event_id) подписчик игнорирует обработку — состояние не изменяется (идемпотентность).
8. Система журналирует доставку и попытки для аудита.
**Альтернативные потоки:**
- A1: Webhook-URL недоступен после всех попыток — событие помечается «недоставлено», система уведомляет оператора и позволяет повторную отправку вручную.
- A2: Подписчик ответил 4xx (payload отклонён) — система не повторяет доставку, событие помечается «отклонено» с сохранением payload для анализа.
- A3: Дубликат события из источника (повторное подтверждение освоения) — система дедуплицирует по признаку module_mastered для пары learner+module и не инициирует повторный каскад.
- A4: Освоение откатывается (ошибочное подтверждение) — система отправляет компенсирующее событие с тем же correlation_id и признаком отмены.
**Постусловия:** Событие `module.mastered` доставлено всем подписчикам или корректно помечено недоставленным/отклонённым; каскад пересчёта выполнен один раз; повторные доставки и дубликаты не изменяют состояние; журнал доставки доступен для аудита.
**Источник требований:** vision.md F6.4 (P8 — платформа не получает события прогресса; G2 — интеграция платформ через события)
