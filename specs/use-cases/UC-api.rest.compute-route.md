### UC-api.rest.compute-route: Вычисление маршрута через REST API

**Актор:** EdTech-платформа (API-клиент)
**Приоритет:** P0
**Ключевая функция:** F6.1
**Канал:** API
**Описание:** Внешняя EdTech-платформа вызывает `GET /routes/compute` для вычисления персонального маршрута учащегося. EduTrack читает онтологию через VEDO Hub, вычисляет маршрут как функцию (текущая позиция + цель + контекст) и возвращает результат; платформа остаётся владельцем контента и аудитории (F6.7).
**Основной поток:**
1. API-клиент аутентифицируется (API-ключ / OAuth) и отправляет `GET /routes/compute` с параметрами: learner_id, текущая позиция (освоенные модули), цель (роль/экзамен/проект/тема), контекст (класс, рамки, педагогическая концепция).
2. Система проверяет аутентификацию и права клиента на данного учащегося; при валидации параметров запускается вычисление.
3. Система копирует релевантный подграф онтологии через API VEDO Hub (модули, достижимые из текущей позиции, с связями и атрибутами) — вычисление выполняется в памяти EduTrack (F1.1).
4. Система выполняет алгоритм маршрутизации: кратчайший путь с весами связей (strict/soft/enrich), учёт essential-ядра, фильтр по формальной рамке (F1.12), приоритет как функция контекста (дедлайн, темп).
5. Система формирует ответ: три горизонта маршрута (дальний, критический путь, ближний), оценка времени (F1.1.5), подборка ресурсов по шагам (F3.2), оценка затрат (F3.4).
6. Система возвращает ответ в формате API (JSON) со статусом 200, идентификатором версии маршрута и временем вычисления.
7. API-клиент применяет маршрут в своей платформе (отображение, интеграция с LMS) и при необходимости подписывается на события пересчёта (F6.4).
**Альтернативные потоки:**
- A1: Некорректные параметры (цель недостижима, неизвестный learner_id) — система возвращает 4xx с описанием ошибки и ближайшими допустимыми значениями.
- A2: Превышение лимита запросов/квоты — система возвращает 429 с Retry-After; клиент повторяет запрос позже.
- A3: VEDO Hub недоступен — система возвращает 503 (кэшированный подграф при наличии) и журналирует сбой для повторной попытки.
- A4: Запрос на пересчёт существующего маршрута при изменении онтологии — вычисление возвращает новую версию маршрута с дельтой к предыдущей (F1.2).
**Постусловия:** Маршрут вычислен по актуальному состоянию онтологии и позиции учащегося; ответ возвращён клиенту с версией маршрута; вычисление не модифицировало онтологию VEDO Hub (только чтение); пересчёты идемпотентны для одинаковых входных параметров.
**Источник требований:** vision.md F6.1 (P7 — платформы строят граф с нуля; P8 — рекомендации без семантики; G2 — API маршрутов для тысяч клиентов)
