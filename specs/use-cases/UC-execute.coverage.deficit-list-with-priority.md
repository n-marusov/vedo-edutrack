### UC-execute.coverage.deficit-list-with-priority: Список дефицитов ФГОС с приоритетом

**Актор:** Система
**Приоритет:** P1
**Ключевая функция:** F2.7
**Канал:** GUI/API
**Описание:** Проекция дефицитов: список незакрытых требований формальной рамки (ФГОС) с приоритетом — жёсткий пререквизит для других тем > часть ядра > опциональное. Дефициты ранжируются по критичности: требование, блокирующее другие требования (через strict-связи) — выше, чем изолированное опциональное. Вход для аттестационной готовности (F2.8), прогноза (F2.5) и приоритизации маршрута (F1.12).

**Основной поток:**
1. Пользователь (GUI) или API-клиент запрашивает список дефицитов ФГОС для ученика (или планировщик запускает расчёт перед контрольной точкой).
2. Система вычисляет покрытие (F2.7): закрытые и незакрытые требования рамки для контекста на актуальной позиции.
3. Система формирует множество дефицитов: незакрытые требования рамки.
4. Детерминированное ядро ранжирует дефициты по приоритету: (1) жёсткий пререквизит для других тем — требование, которое блокирует другие требования/модули через strict-связи; (2) часть ядра — требование из essential-ядра контекста; (3) опциональное — остальные.
5. Внутри каждой группы ядро дополнительно учитывает каскадное влияние: число зависимых требований и модулей, близость к контрольной точке (за N недель до аттестации приоритет дефицитов растёт, F1.12).
6. Система формирует список: каждое требование с приоритетом, статусом (не закрыто / закрыто частично), связанными модулями (какие модули закрывают требование и не освоены), и оценкой усилий.
7. Система привязывает к каждому дефициту рекомендацию: какие модули освоить для закрытия, связь с корневыми лакунами (F2.1), оценка времени (F1.5).
8. Список публикуется в GUI (сортировка по приоритету, фильтры по доменам) и через API (машинно-читаемый формат); используется аттестационной готовностью (F2.8) и построением маршрута.

**Альтернативные потоки:**
- A1: **Нет дефицитов** — все требования рамки закрыты; система сообщает о полном покрытии и не формирует список (или формирует пустой).
- A2: **Нет рамки** — формальная рамка не задана; список дефицитов недоступен, GUI/API возвращает «нет данных».
- A3: **Дефицит с частичным закрытием** — требование закрыто не полностью (освоены не все связанные модули); система помечает «частично» и включает в список с промежуточным приоритетом.
- A4: **Дефицит вне маршрута** — требование не закрыто, но связанные модули не входят в маршрут ученика (конфликт цели и рамки); система помечает дефицит как «требует расширения маршрута» и передаёт в пересмотр плана (F1.9).

**Постусловия:** Список незакрытых требований рамки сформирован и ранжирован по приоритету (жёсткий пререквизит > ядро > опциональное) с учётом каскадного влияния; к каждому дефициту привязаны рекомендации (модули, лакуны, оценка времени); список доступен в GUI и API; использован аттестационной готовностью и маршрутизацией.

**Источник требований:** vision.md F2.7 (P: «видно покрытие, но непонятно, что закрывать в первую очередь»)
