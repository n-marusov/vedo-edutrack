### UC-practice.projects.suggest-cross-subject-projects: Подбор межпредметных проектных идей

**Актор:** Система / Ученик
**Приоритет:** P1
**Ключевая функция:** F5.2
**Канал:** GUI
**Описание:** Система предлагает проектные идеи, требующие знаний из нескольких тем (часто из разных предметов), с указанием необходимых модулей, сложности и ожидаемого результата. Ученик просматривает идеи с учётом своей текущей позиции и выбирает проект для включения в маршрут.
**Основной поток:**
1. Ученик открывает раздел «Проекты» в личном кабинете или из блока рекомендаций дашборда (F4.2).
2. Система определяет доступные комбинации тем: темы, чьи необходимые модули освоены или доступны в ближнем горизонте (F1.3).
3. Система отбирает проектные идеи из онтологии, требующие знаний из нескольких тем/предметов (например, «Спроектируй здание в стиле ренессанс»: геометрия — пропорции + история — Возрождение + искусство), с учётом интересов ученика и карты качеств (F5.4).
4. Для каждой идеи система показывает: необходимые модули (освоенные и недостающие), сложность, ожидаемый результат, связь с ФГОС при наличии.
5. Система ранжирует идеи: полностью доступные — выше, с частично недостающими модулями — ниже, с указанием, что именно нужно освоить.
6. Ученик открывает карточку проекта — видит детали и кнопку «Включить в маршрут».
7. Ученик подтверждает выбор — система формирует целевую позицию проекта и перестраивает маршрут под неё (F4.3: тип цели «проект»).
8. Система фиксирует пересчитанный маршрут и отображает дельту с текущим планом (F1.9).
**Альтернативные потоки:**
- A1: Нет проектов, полностью доступных ученику — система показывает ближайшие варианты с дефицитом 1-2 модуля и оценкой времени до старта.
- A2: Ученик отказывается от включения проекта — выбор не сохраняется, маршрут не перестраивается.
- A3: Методист просматривает проекты для класса — система агрегирует доступность проекта по группе (какая доля учащихся готова) для синхронизации расписания (F1.10).
**Постусловия:** Список проектных идей отфильтрован по доступным комбинациям тем ученика; для каждой идеи указаны необходимые модули, сложность и ожидаемый результат; при подтверждении маршрут перестроен под проект и показана дельта с планом.
**Источник требований:** vision.md F5.2 (P2 — межпредметные связи скрыты; P4 — синхронизация проектного расписания; P21 — знания без практического применения)
