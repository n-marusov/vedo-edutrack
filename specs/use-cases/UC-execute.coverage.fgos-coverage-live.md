### UC-execute.coverage.fgos-coverage-live: Живое покрытие ФГОС

**Актор:** Система
**Приоритет:** P0
**Ключевая функция:** F2.7
**Канал:** Schedule/API
**Описание:** Расчёт покрытия формальной рамки (ФГОС) в реальном времени: `coverage = освоенные модули с привязкой / всего требований` для контекста обучения. Модуль закрывает требование, если привязан к нему в онтологии. Покрытие вычисляется на актуальной позиции ученика и обновляется при каждом изменении позиции (событие `module.mastered`) или рамки (обновление онтологии).

**Основной поток:**
1. Планировщик (Schedule) запускает пересчёт покрытия: при событии `module.mastered` (обновление позиции), при обновлении рамки/привязок в онтологии (F0.3) или периодически перед контрольной точкой.
2. Система загружает формальную рамку для контекста обучения (ФГОС): множество требований и привязки «модуль → требование» из онтологии (F0.1); фиксируется версия рамки.
3. Система определяет позицию ученика: множество освоенных модулей с уровнями.
4. Детерминированное ядро вычисляет покрытие: множество требований, закрытых освоенными модулями (модуль закрывает требование, если привязан к нему), делится на общее число требований для контекста — `coverage = освоенные модули с привязкой / всего требований`.
5. Ядро группирует покрытие по доменам (предметам/разделам рамки) для отчётности (вход F2.8) и формирует список дефицитов — незакрытых требований (F2.7, проекция).
6. Система публикует актуальное покрытие: GUI показывает долю и прогресс-бар по доменам; API отдаёт покрытие с версией рамки и версией онтологии.
7. При изменении позиции или рамки покрытие пересчитывается и обновляется в интерфейсе без запроса пользователя.
8. Покрытие сохраняется как проекция (не документ) и используется прогнозом (F2.5), аттестационной готовностью (F2.8) и построением маршрута (F1.12: приоритет модулей, закрывающих ФГОС-дефициты).

**Альтернативные потоки:**
- A1: **Нет рамки для контекста** — формальная рамка для контекста не задана в онтологии; покрытие не вычисляется, API возвращает «нет данных», аттестационные отчёты недоступны.
- A2: **Модуль без привязки** — освоенный модуль не привязан к требованиям рамки; он не учитывается в числителе покрытия (покрытие не завышается), фиксируется в аудите.
- A3: **Обновление привязок** — методист изменил привязки модуль→требование; покрытие пересчитывается на новой версии рамки, изменение покрытия помечается (дельтой).
- A4: **Недостоверное освоение** — уровень освоения модуля ниже порога с учётом погрешности (F2.2); модуль не считается освоенным для покрытия.

**Постусловия:** Покрытие ФГОС вычислено на актуальной позиции и версии рамки: доля закрытых требований, группировка по доменам, список дефицитов; покрытие обновляется при событиях `module.mastered` и обновлении онтологии; результат доступен в GUI и API с указанием версий; покрытие используется прогнозом и аттестационными отчётами.

**Источник требований:** vision.md F2.7 (P: «школа и родители не видят, закрывает ли обучение требования ФГОС»)
