### UC-execute.coverage.real-vs-formal-knowledge-mapping: Сверка «живого» знания с формальной рамкой

**Актор:** Система
**Приоритет:** P1
**Ключевая функция:** F2.3
**Канал:** GUI/API
**Описание:** Для каждого модуля — маппинг на конкретные формулировки ФГОС: ученик знает тему → система показывает «Вот что именно спросят на аттестации по этой теме». Связывает реальное освоение модулей с формальными требованиями рамки: «живое» знание проецируется на формулировки проверки.

**Основной поток:**
1. Пользователь (ученик/родитель через GUI) или API-клиент запрашивает сверку по модулю/теме: «что из этого спросят на аттестации».
2. Система определяет модуль (освоенный или в работе) и загружает формальную рамку для контекста (ФГОС) с привязками «модуль → требование» из онтологии (F0.1); фиксируется версия рамки.
3. Детерминированное ядро находит формулировки требований, привязанных к модулю: конкретные пункты ФГОС, закрываемые этим модулем.
4. Для каждого требования ядро определяет статус: закрыто (модуль освоен, покрытие F2.7), частично (освоение ниже порога, с погрешностью F2.2) или не закрыто.
5. Система формирует маппинг «знание → формулировка»: для каждой темы модуля — какие формулировки ФГОС соответствуют и что именно будет проверяться (тип задания, уровень освоения по F2.2).
6. Объяснение формируется детерминированным ядром, интерпретируется LLM-модулем («Вот что именно спросят на аттестации по этой теме») и сопровождается оценкой уверенности.
7. Система показывает результат пользователю: таблица «тема модуля ↔ формулировка ФГОС ↔ статус ↔ что будет на проверке», с переходом к дефицитам (F2.7) и рекомендациям по доосвоению.
8. Результат доступен через API (машинно-читаемый маппинг) для интеграций (LMS, отчётность школы).

**Альтернативные потоки:**
- A1: **Модуль без привязки к рамке** — к модулю не привязаны требования ФГОС; система сообщает «нет прямого соответствия» и показывает ближайшие связанные требования через связи модуля (например, через предмет).
- A2: **Частичное освоение** — модуль освоен ниже порога; маппинг показывает статус «частично» с указанием погрешности и что именно нужно доосвоить.
- A3: **Изменение формулировок рамки** — методист обновил привязки/формулировки; маппинг пересчитывается на новой версии рамки, изменения помечаются дельтой.
- A4: **Нет рамки для контекста** — формальная рамка не задана; сверка недоступна, GUI/API возвращает «нет данных».

**Постусловия:** Маппинг «живое знание → формулировки ФГОС» сформирован для модуля: конкретные требования, статус закрытия (закрыто/частично/не закрыто), что именно будет проверяться на аттестации; объяснение сформировано и показано пользователю; результат доступен через GUI и API с указанием версии рамки.

**Источник требований:** vision.md F2.3 (P: «ученик не понимает, как знание темы соотносится с тем, что спросят на аттестации»)
