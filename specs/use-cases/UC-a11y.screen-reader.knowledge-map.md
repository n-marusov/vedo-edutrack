### UC-a11y.screen-reader.knowledge-map: Карта знаний для screen reader

**Актор:** Пользователь со screen reader (NVDA / VoiceOver / JAWS)
**Приоритет:** P0
**Ключевая функция:** cross-cutting (WCAG 2.1 AA)
**Канал:** GUI
**Описание:** Карта знаний (F4.1) и карта лакун (F4.6) доступны через screen reader: семантическая структура DOM, текстовые альтернативы для графа, корректные ARIA-атрибуты, навигация по узлам графа без визуального восприятия. Пользователь получает эквивалентную информацию о прогрессе, лакунах и каскадном влиянии.
**Основной поток:**
1. Пользователь со screen reader открывает карту знаний.
2. Система предоставляет семантическую структуру: заголовки, списки, landmarks (header, main, navigation).
3. Система обеспечивает текстовую альтернативу графу: список узлов с прогрессом (освоено/в процессе/доступно/заблокировано) в порядке критичности.
4. Пользователь переходит в режим «Критический путь» (одно нажатие) — screen reader озвучивает essential-модули и strict-связи.
5. Пользователь выбирает узел — система озвучивает: статус, лакуна (если есть), каскадное влияние («эта лакуна блокирует 4 темы в 3 предметах»).
6. Пользователь переключается в режим «Лакуны» — screen reader озвучивает корневые лакуны и их блокирующее влияние, ранжированное по каскадному эффекту.
**Альтернативные потоки:**
- A1: Граф не может быть представлен списком (слишком большой) — система предоставляет поиск по узлу и навигацию по уровням глубины.
- A2: Динамическое обновление карты (пересчёт маршрута) — система озвучивает изменения через aria-live (политично, без перебивания ввода).
- A3: Отсутствуют текстовые альтернативы у графических элементов — фиксируется как критический дефект доступности (WCAG 1.1.1).
**Постусловия:** Пользователь со screen reader получил полную информацию карты знаний/лакун (прогресс, статусы, лакуны, каскадное влияние) эквивалентно визуальному представлению.
**Источник требований:** vision.md F4.1, F4.6, WCAG 2.1 AA (1.1.1 Non-text Content, 1.3.1 Info and Relationships, 4.1.2 Name/Role/Value)
