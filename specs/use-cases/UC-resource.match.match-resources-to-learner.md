### UC-resource.match.match-resources-to-learner: Подбор ресурсов под предпочтения ученика

**Актор:** Система
**Приоритет:** P1
**Ключевая функция:** F3.2
**Канал:** Schedule
**Описание:** Фоновая задача автоматически подбирает ресурсы для каждого шага маршрута под профиль предпочтений ученика: формат, стиль обучения, сложность, длительность и бюджет. Запускается по расписанию и при каскадном пересчёте маршрута (F1.6).
**Основной поток:**
1. Триггер запуска: сработал Schedule (например, еженедельная проверка «что нового доступно», F1.2) или завершён пересчёт маршрута.
2. Система загружает профиль предпочтений ученика: предпочитаемые форматы (video до 20 минут, interactive и т.п.), стиль, диапазон сложности, лимит длительности, бюджет на ресурсы.
3. Система берёт текущий маршрут и для каждого шага получает из онтологии VEDO Hub через API список привязанных контент-ресурсов и ресурсов обеспечения (F3.1).
4. Система фильтрует ресурсы по формату, стилю, сложности, длительности и стоимости относительно профиля.
5. Система ранжирует оставшиеся ресурсы по релевантности: совпадение формата и стиля > близость сложности > длительность > стоимость.
6. Система прикрепляет топ-N ресурсов к каждому шагу маршрута, помечая соответствие профилю (exact match / близкое / запасной вариант).
7. Система обновляет подборку ресурсов и оценку бюджета маршрута (F3.4).
8. Система записывает результат подбора и, если появились существенно более подходящие ресурсы, уведомляет ученика/родителя в личном кабинете.
**Альтернативные потоки:**
- A1: Для шага нет ресурсов, совпадающих с профилем — система выбирает ближайший вариант по формату/стилю и помечает его как «компромиссный», либо помечает шаг как «требует ресурса».
- A2: Суммарная стоимость подборки превышает бюджет — система сокращает список до бюджетного набора и передаёт нехватку как ограничение доступности (F3.3).
- A3: В онтологии появился новый ресурс, лучше совпадающий с профилем — подборка пересчитывается при следующем Schedule-запуске, повторный запуск идемпотентен.
**Постусловия:** Каждый шаг маршрута обеспечен подборкой ресурсов, согласованной с профилем предпочтений и бюджетом; подборка привязана к версии маршрута; состояние повторного запуска идемпотентно — повторный прогон не дублирует и не портит подборку.
**Источник требований:** vision.md F3.2 (P1 — потеря времени на неоптимальных материалах; P20 — ресурсы выясняются в момент, когда они уже нужны)
