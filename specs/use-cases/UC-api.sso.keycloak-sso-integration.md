### UC-api.sso.keycloak-sso-integration: Интеграция Enterprise SSO через Keycloak

**Актор:** Корпоративный клиент
**Приоритет:** P1
**Ключевая функция:** F6.5
**Канал:** Mixed (API + GUI)
**Описание:** Для корпоративных клиентов (Enterprise) доступна аутентификация через Keycloak по протоколам SSO/SAML: вход в EduTrack через корпоративный IdP (SP-initiated SSO), единый выход (logout), управление сессией. Пользователь попадает в контекст своего департамента (HR/L&D, онбординг) без отдельной учётной записи EduTrack.
**Основной поток:**
1. Сотрудник корпоративного клиента открывает EduTrack и выбирает вход «Через корпоративный портал».
2. Система (SP) инициирует SSO: формирует SAML AuthnRequest (или OIDC authorization request) и перенаправляет пользователя на IdP Keycloak клиента.
3. Пользователь аутентифицируется в корпоративном IdP (пароль, MFA — на стороне IdP).
4. IdP возвращает утверждение (assertion/токен) на ACS-эндпоинт EduTrack; система проверяет подпись, аудиторию, срок действия и маппинг атрибутов (employee_id, email, роль, департамент).
5. Система сопоставляет атрибуты с учётной записью EduTrack: существующая связывается, новая создаётся автоматически (JIT-провижининг) с ролью по атрибутам (HR/L&D, сотрудник).
6. Система создаёт сессию и направляет пользователя в контекст департамента: дашборд HR (F4.4), панель группы (F4.7) или личный маршрут сотрудника.
7. Пользователь завершает работу и нажимает «Выйти» — система инициирует единый выход (SLO): завершает сессию EduTrack и направляет LogoutRequest в Keycloak.
8. IdP завершает сессии подключённых сервисов и возвращает подтверждение — система завершает локальную сессию и показывает экран входа.
**Альтернативные потоки:**
- A1: Атрибуты IdP неполные (нет роли/департамента) — система создаёт учётную запись с ролью по умолчанию и помечает профиль «требует уточнения» для администратора клиента.
- A2: Истёк срок сертификата/подписи IdP — система отклоняет утверждение с понятной ошибкой и уведомляет администратора клиента.
- A3: Пользователь уже аутентифицирован в IdP (session exists) — IdP пропускает повторный ввод пароля, система сразу создаёт/продлевает сессию EduTrack.
- A4: SLO не поддержан IdP — система завершает только локальную сессию и показывает предупреждение о незавершённых сессиях других сервисов.
- A5: Доступ запрещён по политике клиента (уволен, вне департамента) — система отклоняет вход с 403 и не создаёт учётную запись.
**Постусловия:** Пользователь аутентифицирован через корпоративный IdP Keycloak (SP-initiated SSO); учётная запись связана/создана с корректными ролью и контекстом департамента; сессия управляется, единый выход выполнен; политики доступа клиента соблюдены.
**Источник требований:** vision.md F6.5 (P9, P19 — корпоративный онбординг; G6 — Enterprise-контекст; требования корпоративных клиентов к SSO/SAML)
