### UC-a11y.navigation.keyboard-route-builder: Навигация по конструктору маршрутов с клавиатуры

**Актор:** Пользователь с ограниченными возможностями (keyboard-only)
**Приоритет:** P1
**Ключевая функция:** cross-cutting (WCAG 2.1 AA)
**Канал:** GUI
**Описание:** Конструктор маршрутов (F4.3) полностью управляется с клавиатуры: все интерактивные элементы доступны, фокус видим, отсутствуют клавиатурные ловушки. Пользователь может выбрать цель, просмотреть маршрут, оценить время и подтвердить фиксацию плана без использования мыши.
**Основной поток:**
1. Пользователь открывает конструктор маршрутов и фокусируется на поле выбора цели (клавиша Tab).
2. Система обеспечивает видимый индикатор фокуса (focus ring) на каждом интерактивном элементе.
3. Пользователь выбирает цель через комбинированный список (клавиши стрелок + Enter) или прямой ввод.
4. Система отображает визуализацию маршрута и оценку времени; пользователь переходит к кнопке «Подтвердить» (Tab/Shift+Tab).
5. Пользователь подтверждает фиксацию плана клавишей Enter.
6. Система фиксирует план и сообщает об успехе (визуально и через screen reader: aria-live-регион).
**Альтернативные потоки:**
- A1: Пользователь не может завершить действие — фокус застревает в элементе (клавиатурная ловушка). Система обеспечивает выход (Esc / Shift+Tab) — проверка отсутствия ловушек входит в критерии приёмки.
- A2: Ошибка валидации цели — система показывает сообщение об ошибке и возвращает фокус к проблемному полю (WCAG 3.3.1, 3.3.3).
- A3: Пользователь использует скринридер — все элементы имеют корректные ARIA-роли и доступные имена.
**Постусловия:** Пользователь выполнил полный цикл конструктора (выбор цели → визуализация → подтверждение) без использования мыши; план зафиксирован или пользователь осознанно отменил.
**Источник требований:** vision.md F4.3, WCAG 2.1 AA (2.1.1 Keyboard, 2.1.2 No Keyboard Trap, 2.4.7 Focus Visible)
