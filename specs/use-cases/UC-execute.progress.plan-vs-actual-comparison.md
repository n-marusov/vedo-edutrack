### UC-execute.progress.plan-vs-actual-comparison: Сверка «план и факт» по шагам плана

**Актор:** Система
**Приоритет:** P0
**Ключевая функция:** F2.4
**Канал:** Schedule
**Описание:** Для каждого модуля зафиксированного плана — сопоставление плановой и фактической даты завершения: отклонение в днях и причина отклонения (ускорение / требовалось больше практики / перерыв). Основа управления по отклонениям: превышение допуска порождает событие `PlanDeviationDetected` и пересмотр прогноза (F2.5), а превышение порога уведомлений — уведомление (F2.6).

**Основной поток:**
1. Планировщик (Schedule) запускает сверку план-факт: периодически (например, ежедневно/еженедельно), при событии освоения модуля (`module.mastered`) или при наступлении плановой даты шага.
2. Система берёт зафиксированный план (снэпшот с плановыми датами) и фактическую траекторию (упорядоченные по времени освоения с датами).
3. Для каждого шага плана система сопоставляет плановую дату завершения с фактической датой освоения и вычисляет отклонение в днях (положительное — опоздание, отрицательное — ускорение).
4. Для шагов с отклонением система фиксирует причину: ускорение / требовалось больше практики / перерыв / изменение объёма (причина вводится автоматически по паттерну или уточняется учеником/родителем).
5. Система сверяет отклонение с допуском плана (±15% по срокам, порог по дням): при выходе за допуск публикуется событие `PlanDeviationDetected` (план девиирован).
6. Событие `PlanDeviationDetected` запускает каскад: пересмотр прогноза (F2.5), при превышении порога уведомлений N дней — уведомление родителю/HR/ученику (F2.6), при провале контрольной точки — предложение пересмотра плана (F1.9).
7. Система обновляет отчёт «план и факт»: таблица шагов с плановой/фактической датой, отклонением в днях и причиной; статусы шагов (запланирован → доступен → в работе → освоен → подтверждён).
8. Обновлённый отчёт публикуется в GUI/API и используется прогнозом (F2.5) и дашбордами.

**Альтернативные потоки:**
- A1: **Модуль вне плана** — ученик освоил модуль, которого нет в зафиксированном плане (другая ветка); система фиксирует факт в траектории, в сверку план-факт не включает, но помечает расхождение маршрута и плана (F1.9).
- A2: **Плана нет** — план не зафиксирован; сверка план-факт недоступна, система показывает только траекторию (факт) без отклонений.
- A3: **Отклонение в допуске** — отклонение меньше допуска; событие `PlanDeviationDetected` не публикуется, сверка фиксирует отклонение как информационное.
- A4: **Причина не определена** — автоматический вывод причины неоднозначен; система помечает шаг «причина не указана» и запрашивает уточнение у пользователя.

**Постусловия:** Для каждого шага плана зафиксированы плановая и фактическая даты, отклонение в днях и причина; событие `PlanDeviationDetected` опубликовано при выходе за допуск; каскад (прогноз F2.5, уведомления F2.6, пересмотр плана F1.9) запущен при необходимости; отчёт «план и факт» обновлён и доступен.

**Источник требований:** vision.md F2.4 (P: «родитель узнаёт об отставании постфактум, без причин»)
