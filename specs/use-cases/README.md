# Прецеденты использования — VEDO EduTrack

В этой директории находятся отдельные файлы прецедентов использования (Use Cases) проекта VEDO EduTrack — сервиса образовательных маршрутов на базе VEDO Hub. Каждый файл соответствует одному UC и назван по шаблону `<UC-ID>.md`.

---

## Формат идентификатора UC

```
UC-<L1>.<L2>.<L3>
```

Где:

| Часть | Описание | Допустимые значения |
|-------|----------|---------------------|
| **L1** | Домен (соответствует F1–F6 vision.md) | `plan` · `execute` · `resource` · `viz` · `practice` · `api` · `a11y` |
| **L2** | Поддомен | `compute` · `trigger` · `horizon` · `fixation` · `recalculation` · `schedule` · `constraint` · `progress` · `gap` · `assessment` · `coverage` · `forecast` · `alert` · `attestation` · `catalog` · `match` · `availability` · `budget` · `map` · `dashboard` · `builder` · `panel` · `stories` · `projects` · `qualities` · `recommendation` · `rest` · `sparql` · `webhooks` · `lms` · `sso` · `mcp` · `navigation` · `screen-reader` · `keyboard` |
| **L3** | Семантический англоязычный тег в kebab-case, отражающий суть UC | Свободная семантическая метка (не ограничена глаголами) |

### Правила именования

1. Только **kebab-case**, без цифр и индексов.
2. **L1** — строго из списка доменов.
3. **L3** — свободная семантическая метка, отражающая конкретный сценарий.
4. UC моделируют не только GUI-сценарии: допустимы GUI, API, CLI, Webhook/Event, Schedule/Job.
5. Для каждого UC рекомендуется указывать метаданные `**Канал:** GUI | API | CLI | Webhook | Schedule | Mixed`.

### Примеры

| ✅ Корректно | ❌ Некорректно |
|---|---|
| `UC-plan.compute.shortest-path-to-goal` | `UC-1.plan.compute` |
| `UC-execute.gap.diagnose-root-cause` | `UC-execute.gap.diagnose` (слишком коротко) |
| `UC-resource.catalog.filter-by-format` | `UC-resource.catalog.filterByFormat` (camelCase) |
| `UC-viz.map.view-knowledge-graph-with-progress` | `UC-viz.map.viewing` (не kebab-case) |
| `UC-api.rest.compute-route-for-learner` | `UC-api.rest.1` (содержит цифру) |

## Формат описания UC

Каждый файл UC содержит следующие секции:

| Секция | Обязательность | Описание |
|--------|---------------|----------|
| `### <UC-ID>: <Название>` | Обязательно | Заголовок с идентификатором и кратким названием на русском |
| `**Актор:**` / `**Акторы:**` | Обязательно | Роль(и) пользователя, инициирующего прецедент |
| `**Приоритет:**` | Обязательно | `P0` (критичный), `P1` (высокий), `P2` (средний) |
| `**Ключевая функция:**` | Обязательно | Ссылка на функции из `vision.md` (F1–F6) |
| `**Канал:**` | Рекомендуется | `GUI` / `API` / `CLI` / `Webhook` / `Schedule` / `Mixed` |
| `**Описание:**` | Обязательно | Краткое описание прецедента |
| `**Основной поток:**` | Обязательно | Нумерованный список шагов основного сценария |
| `**Альтернативные потоки:**` | Рекомендуется | Варианты (A1, A2, ...) с описанием отклонений |
| `**Постусловия:**` | Обязательно | Состояние системы после успешного выполнения UC |
| `**Источник требований:**` | Рекомендуется | Ссылка на файл(ы) требований |

## Домены UC

| Домен (L1) | Соотв. функции (vision.md) | Описание | Пример UC-ID |
|------------|---------------------------|----------|-------------|
| `plan` | F1. Планирование маршрута | Вычисление маршрута, триггеры перестройки, горизонты, фиксация плана, пересчёт, синхронизация расписания, входные ограничения | `UC-plan.compute.shortest-path-to-goal` |
| `execute` | F2. Исполнение плана | Прогресс, план-факт, диагностика лакун, проверочные задания, покрытие ФГОС, прогноз, уведомления, аттестация | `UC-execute.gap.diagnose-root-cause` |
| `resource` | F3. Ресурсы | Каталог, подбор под ученика, доступность, затраты и бюджет | `UC-resource.catalog.filter-by-format` |
| `viz` | F4. Визуализация | Карта знаний, дашборды, конструктор маршрутов, карта лакун, панель группы | `UC-viz.map.view-knowledge-graph-with-progress` |
| `practice` | F5. Связь с практикой и жизнью | Истории, проектные идеи, рекомендации, карта качеств | `UC-practice.stories.recommend-at-mastery` |
| `api` | F6. Интеграции | REST API, SPARQL, коннекторы LMS, webhooks, SSO, MCP | `UC-api.rest.compute-route-for-learner` |
| `a11y` | — (сквозная) | Доступность: screen reader, keyboard-only навигация | `UC-a11y.navigation.keyboard-route-builder` |
| `onboarding` | — (сквозная, публичная витрина) | Вход пользователя в продукт: посадочная страница, регистрация | `UC-onboarding.landing.explore-value-proposition` |

## Специфика EduTrack

- **Маршрут — функция, не документ**: UC на вычисление маршрута (`plan`) описывают пересчёты, а не CRUD.
- **Внешняя онтология**: VEDO EduTrack читает онтологию через VEDO Hub. UC не описывают редактирование онтологии — это зона VEDO Core.
- **События предметной области**: `module.mastered`, `plan.deviated`, `route.recalculated` — триггеры каскадных пересчётов; UC должны явно описывать эти каскады.
- **Канал** для автоматических сценариев (пересчёт маршрута при прогрессе, вебхук `plan.deviated`) — `Webhook` или `Schedule`, не `GUI`.
