# REQ-FR-api.hub.read-ontology

**Приоритет:** P0
**Ключевая функция:** F0.1
**Источник:** vision.md F0.1, 1.7 (граница Hub/EduTrack); REQ-NFR-api.availability.hub-dependency-sla

**Описание:** Сервис должен читать онтологию VEDO Hub через REST API и MCP-сервер (read-only): модули (KnowledgeModule), пять типов межпредметных связей (`hasStrictPrerequisite`, `hasSoftPrerequisite`, `enriches`, `appliesTo`, `isAnalogousTo`), ФГОС-привязки, ресурсы, истории, проектные идеи, педагогические концепции. EduTrack не редактирует онтологию (read-only); версия онтологии фиксируется для воспроизводимости вычислений. Требование закрывает лакуну F0.1 FR-слоя: «без F0 сервис не функционирует» (vision 1.7).

**Критерии приёмки:**
- Чтение онтологии выполняется через REST API Hub (контракт в OpenAPI) и MCP-сервер; операции записи/редактирования не предусмотрены (0 мутирующих вызовов к Hub из сервиса — проверка тестом).
- Чтение покрывает все 5 типов связей и все типы сущностей (модули, ФГОС-привязки, ресурсы, истории, проектные идеи, концепции): 100% запрошенных сущностей возвращаются.
- Таймауты запросов к Hub ≤ 3 секунд; при недоступности Hub применяется режим деградации (офлайн-кэш 24 ч, см. REQ-NFR-api.availability.hub-dependency-sla).
- Версия онтологии фиксируется при каждом чтении и сохраняется в результатах вычислений (для воспроизводимости, согласуется с REQ-FR-plan.compute.shortest-path).
- Доля успешных чтений при доступном Hub ≥ 99.5% за месяц (согласуется с REQ-NFR-api.availability.hub-dependency-sla).
