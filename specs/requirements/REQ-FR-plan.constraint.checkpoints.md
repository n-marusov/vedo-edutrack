# REQ-FR-plan.constraint.checkpoints

**Приоритет:** P0
**Ключевая функция:** F1.11
**Источник:** UC-plan.constraint.apply-checkpoints-and-fgos; vision.md F1.11 (P: «план не учитывает даты аттестации и требования ФГОС»)
**Описание:** Входные ограничения для генерации плана: контрольные точки (даты аттестации, конец четверти) и формальные рамки (ФГОС, профстандарт) из онтологии (F0.1). План генерируется под эти ограничения: для каждой контрольной точки определяется целевое покрытие рамки (требования, которые должны быть закрыты освоенными модулями к дате), и шаги распределяются так, чтобы целевое покрытие достигалось к дате, с учётом норм нагрузки и доступного времени. Ограничения сохраняются как атрибуты плана (версия рамки). При невыполнимости фиксируется риск и предлагаются варианты (увеличить нагрузку, сдвинуть цель, сократить состав) — решение принимает пользователь. При изменении дат контрольных точек план пересчитывается под новые даты.

**Критерии приёмки:**
- Учёт ограничений: 100% контрольных точек контекста обучения (типы: аттестация, конец четверти), присутствующих в онтологии, учитываются при генерации плана (0 пропущенных контрольных точек).
- Целевое покрытие к дате: для 100% сгенерированных выполнимых планов к дате контрольной точки расчётное покрытие рамки ≥ целевого покрытия (расхождение = 0); шаги распределены с учётом норм нагрузки.
- Обработка невыполнимости (A1): если целевое покрытие недостижимо при текущих ограничениях (нагрузка, темп), система формирует предупреждение о риске с ≥ 1 вариантом и передаёт решение пользователю — 0 планов, сгенерированных без предупреждения при невыполнимости.
- Обновление дат (A2): при переносе контрольной точки в онтологии/календаре план пересчитывается под новые даты в течение ≤ 15 мин, пользователю показывается дельта — 0 планов с устаревшими датами после обновления.
- Сохранение ограничений: версия рамки (ФГОС/профстандарт) и даты контрольных точек сохраняются как атрибуты плана — 100% планов содержат версию рамки, доступную для аудита.
- Отсутствие рамки (A3): для контекста без формальной рамки покрытие не рассчитывается (вывод «нет данных»), генерация плана завершается без ошибок (0 сбоев).
- Обновление рамки (A4): при обновлении ФГОС-привязок в онтологии планы пересчитываются с новой версией рамки по каскаду F1.2 (0 планов со старой версией рамки после обновления).
