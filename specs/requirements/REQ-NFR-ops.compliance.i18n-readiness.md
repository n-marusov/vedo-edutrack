# REQ-NFR-ops.compliance.i18n-readiness

**Приоритет:** P2
**Ключевая функция:** cross-cutting (локализация/интернационализация)
**Источник:** quality-matrix audit ячейка 2.2 (Эргономика/Эксплуатация — локализация), vision.md M10 (мультиязычность RU+EN), RESEARCH.md (решения от 2026-08-02); практика: интернационализация после выхода в продакшн дороже гигиены на старте

**Описание:** Система обязана быть готова к локализации: поддерживать русский (основной, `language.ui: ru`) и английский (M10) языки и обеспечивать лёгкое добавление новых языков — только файлы переводов и конфигурация, без изменений кода. Требование закрывает неучтённый аспект «локализация» ячейки 2.2: разные языковые группы пользователей. RTL-поддержка (арабский, иврит) — явно вне scope до появления решения о соответствующем рынке.

**Критерии приёмки:**
- Экстернализация строк: 100% пользовательских строк UI вынесены из кода в файлы переводов (0 захардкоженных строк); проверка — автоматический скан в CI (i18next-scanner или эквивалент) даёт 0 находок.
- Добавление языка без изменения кода: добавление новой локали = файл переводов + запись в конфигурации; детерминированный тест — добавление тестовой локали проходит полный набор тестов и сборку без правки кода (0 изменений в компонентах/бизнес-логике).
- Гейт покрытия: язык становится доступен пользователю в UI только при 100% переводе всех пользовательских строк; недостающие переводы отображаются на русском (fallback на основной язык) — проверяется тестом покрытия переводов.
- Плюрализация по ICU MessageFormat: русский — 3 формы (1 модуль / 2 модуля / 5 модулей), английский — 2 формы (1 module / 2 modules); локаль-тесты для каждой поддерживаемой локали проходят 100%.
- Форматирование по CLDR: даты, числа, валюта форматируются по правилам локали (например, десятичный разделитель «3,14» vs «3.14»); локаль-тесты проходят 100%.
- Доступность в локали: автоматический a11y-аудит (axe-core) в каждой поддерживаемой локали показывает 0 critical-нарушений (согласуется с REQ-NFR-ui.compliance.wcag-level).
- Трудоёмкость: инженерные работы по добавлению нового языка (без перевода) ≤ 1 человеко-дня; замеряется при добавлении английского языка в M10.
- Документация: пользовательская документация локализуется вместе с UI (согласуется с REQ-NFR-ops.compliance.user-documentation); для каждой локали документация покрывает 100% пользовательских сценариев.
