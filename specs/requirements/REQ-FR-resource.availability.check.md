# REQ-FR-resource.availability.check

**Приоритет:** P1
**Ключевая функция:** F3.3
**Источник:** UC-resource.availability.check-availability-and-alternatives (P20)
**Описание:** Для каждого шага маршрута система проверяет доступность ресурсов: расписание репетитора/наставника, статус лабораторного оборудования и достаточность бюджета. Недоступность ресурса фиксируется как ограничение планирования (scheduling constraint) для данного шага и распространяется на последующие шаги маршрута.
**Критерии приёмки:**
- Для каждого шага маршрута выполняется проверка доступности; результат дихотомический: available / unavailable для трёх аспектов — tutor (слот в расписании), equipment (статус), budget (достаточность средств).
- 100% шагов маршрута получают проверку — ни один шаг не пропускается.
- Точность проверки: статус, возвращаемый системой, совпадает с эталонным статусом источника данных на тестовой выборке из 50 шагов (100% совпадение).
- При недоступности ресурса система записывает scheduling constraint для шага и автоматически учитывает его при планировании всех последующих шагов маршрута.
- Проверка учитывает текущую дату и время; доступные окна будущих слотов отображаются явно.
