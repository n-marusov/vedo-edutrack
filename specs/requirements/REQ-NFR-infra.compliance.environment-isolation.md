# REQ-NFR-infra.compliance.environment-isolation

**Приоритет:** P1
**Ключевая функция:** cross-cutting (инфраструктура/безопасность)
**Источник:** quality-matrix audit ячейки 1.1/2.1 (Среда/Эргономика — Разработка), развитие REQ-NFR-infra.compliance.community-enterprise-isolation; уроки опыта: утечки production-ПДн через незащищённые dev/staging-окружения (инциденты 2020–2025)

**Описание:** Окружения dev/staging/prod обязаны быть изолированы, а production-данные (особенно персональные) не должны попадать в окружения разработки, поскольку утечки через незащищённые среды разработки — регулярный инцидент безопасности. Требование закрывает неучтённый аспект «изоляция сред разработки» ячеек 1.1 и 2.1.

**Критерии приёмки:**
- Сегментация: dev/staging/prod — изолированные сети/аккаунты; отсутствие прямого сетевого пути prod → dev (0 открытых портов между окружениями, проверка сетевым сканом).
- Production-данные в dev: использование реальных ПДн в dev/staging запрещено; используются синтетические или анонимизированные данные; проверка — сканер чувствительных данных в dev-БД = 0 совпадений с реальными ПДн.
- Доступ: разработчики имеют доступ к dev/staging; доступ к prod — только по REQ-NFR-ops.access.production-control (read-only/JIT, 2-person rule для деструктивных операций).
- Онбординг: окружение разработчика поднимается по REQ-NFR-process.dev.engineering-gates (`make up` ≤ 30 минут) без доступа к prod-секретам; секреты dev-окружения отдельны от prod (0 общих секретов — проверка сканером).
- Требование не противоречит REQ-NFR-infra.compliance.community-enterprise-isolation (изоляция Community/Enterprise-контуров) — дополняет его изоляцией сред ЖЦ.
