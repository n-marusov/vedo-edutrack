# REQ-FR-execute.coverage.real-vs-formal

**Приоритет:** P1
**Ключевая функция:** F2.3
**Источник:** UC-execute.coverage.real-vs-formal-knowledge-mapping; vision.md F2.3 (P14)
**Описание:** Маппинг «живого» знания на формулировки ФГОС: для каждого модуля система находит требования рамки, привязанные к нему в онтологии («модуль → требование»), определяет статус закрытия (закрыто — модуль освоен; частично — освоение ниже порога с погрешностью F2.2; не закрыто) и показывает ученику/родителю: «Вот что именно спросят на аттестации по этой теме» — тип задания и уровень освоения по F2.2. Объяснение формируется детерминированным ядром и интерпретируется LLM-модулем с оценкой уверенности. Результат — таблица «тема модуля ↔ формулировка ФГОС ↔ статус ↔ что будет на проверке» с переходом к дефицитам (F2.7) и рекомендациям по доосвоению; доступен в GUI и API (машинно-читаемый маппинг) с указанием версии рамки.
**Критерии приёмки:**
- Полнота: для 100% модулей с привязкой к рамке сформирован маппинг «тема модуля ↔ формулировка ФГОС ↔ статус ↔ что будет на проверке» (проверка на тестовом наборе ≥20 модулей).
- Статусы закрытия в маппинге совпадают с актуальными значениями F2.7 для тех же требований (расхождение 0).
- Для каждого требования указано «что именно будет проверяться»: тип задания и уровень освоения (F2.2); корректность подтверждается сверкой с привязками онтологии, LLM-интерпретация сопровождается оценкой уверенности.
- Результат доступен в GUI (таблица) и через API (машинно-читаемый маппинг) с указанием версии рамки.
- При обновлении привязок/формулировок рамки маппинг пересчитывается на новой версии; изменения помечаются дельтой (A3 UC).
- Для модуля без привязки к рамке система показывает «нет прямого соответствия» и ближайшие связанные требования через связи модуля (например, через предмет) (A1 UC).
