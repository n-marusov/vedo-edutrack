# REQ-NFR-infra.compliance.dev-regulatory-constraints

**Приоритет:** P1
**Ключевая функция:** cross-cutting (разработка/комплаенс)
**Источник:** quality-matrix audit ячейка 1.1 (Среда/Разработка — регуляторные ограничения на процесс), развитие REQ-NFR-infra.compliance.oss-licensing; практика: санкционные/экспортные ограничения на компоненты и процесс разработки

**Описание:** Процесс разработки обязан учитывать регуляторные и корпоративные ограничения среды: экспортные ограничения, отраслевые регламенты, требования к среде разработки — с документированным реестром применяемых ограничений и автоматической проверкой соответствия. Требование углубляет ячейку 1.1 (Среда/Разработка) с 🟡 до 🟢.

**Критерии приёмки:**
- Реестр ограничений: документированный перечень регуляторных/корпоративных ограничений на разработку (лицензии, экспортные ограничения, отраслевые стандарты, политики использования AI-инструментов); обновляется при изменении; актуальность = 100% (сверка = 0 расхождений).
- Соответствие в CI: проверка соответствия разрабатываемого кода ограничениям (запрещённые библиотеки/паттерны) — 0 нарушений = гейт релиза.
- Экспортные ограничения: используемые компоненты и сервисы проверяются на экспортные/санкционные ограничения; 0 нарушений (скан в CI).
- Отраслевые регламенты: для образовательного домена учитываются требования к обработке данных несовершеннолетних (privacy by design при разработке) — проверяется чек-листом в каждом значимом PR.
- Согласуется с REQ-NFR-infra.compliance.oss-licensing (лицензии) и REQ-NFR-infra.compliance.environment-isolation (среда).
