# REQ-FR-api.sso.keycloak

**Приоритет:** P1
**Ключевая функция:** F6.5
**Источник:** UC-api.sso.keycloak-sso-integration

**Описание:** Сервис должен интегрироваться с Keycloak для корпоративного Single Sign-On (SSO) по протоколам OIDC и SAML 2.0 (SP-initiated flow): пользователь аутентифицируется через корпоративный IdP, сервис принимает токен/ассерцию, связывает её с локальной учётной записью и управляет сессией (вход, logout, истечение срока). Роли и группы из IdP должны маппиться на роли EduTrack (learner, parent/HR, methodologist, admin).

**Критерии приёмки:**
- SP-initiated SSO работает по OIDC (Authorization Code + PKCE) и SAML 2.0: неаутентифицированный пользователь перенаправляется на Keycloak, после успешной аутентификации получает сессию в EduTrack; полный цикл входа завершается за время не более 5 секунд (p95) на эталонном окружении.
- Logout из EduTrack завершает сессию в EduTrack и (при поддержке single logout) в IdP; после logout доступ к защищённому ресурсу возвращает `401 Unauthorized` с редиректом на login.
- Сессия ограничена по времени: неактивная сессия завершается по истечении конфигурируемого таймаута (по умолчанию 30 минут); по истечении access token (по умолчанию 15 минут) сервис обновляет его через refresh token без повторного ввода учётных данных.
- Роли IdP маппятся на роли EduTrack: пользователь с ролью `methodologist` в Keycloak получает доступ к methodologist-функциям, а к данным learner других пользователей — `403 Forbidden` (проверяется тестом ролевого доступа для каждой роли).
