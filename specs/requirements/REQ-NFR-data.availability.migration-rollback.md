# REQ-NFR-data.availability.migration-rollback

**Приоритет:** P1
**Ключевая функция:** cross-cutting (данные/сопровождение)
**Источник:** quality-matrix audit ячейка 4.3 (Аварии/Сопровождение — неудачное обновление), развитие REQ-NFR-data.availability.backup-validity; уроки опыта: неудачная миграция БД без rollback → потеря данных и длительный простой (класс инцидентов, смежный с GitLab 2017)

**Описание:** Обновление схемы БД обязано иметь обратимые миграции (forward/backward) с автоматическим откатом при сбое, поскольку неудачная миграция без rollback приводит к потере данных и простою. Требование закрывает неучтённый аспект «откат неудачного обновления» ячейки 4.3.

**Критерии приёмки:**
- Каждая миграция имеет обратимый шаг (down-migration): 100% миграций поддерживают откат; миграции без обратимого шага запрещены (гейт в CI).
- Автоматический откат: при сбое миграции (ошибка, частичное применение) система автоматически откатывает к предыдущей схеме ≤ 15 минут без ручного вмешательства.
- Тест обратимости: для каждой миграции выполняется up→down→up тест в CI; 100% миграций проходят (0 сбоев).
- Откат миграции не нарушает целостность данных: после rollback расхождение контрольных сумм с точкой до миграции = 0 (согласуется с REQ-NFR-data.availability.backup-validity).
- Миграции применяются в окно сопровождения; изменение схемы без обратимого шага блокирует релиз.
