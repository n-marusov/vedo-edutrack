# REQ-FR-plan.compute.pedagogy-concept

**Приоритет:** P2
**Ключевая функция:** F1.7
**Источник:** vision.md F1.7 (этап 2 — вне MVP; концептуальная онтология пополняется сообществом)
**Описание:** [Этап 2, вне MVP.] Маршрут строится с учётом выбранной педагогической концепции: фильтрация и группировка модулей в соответствии с концепцией. Примеры: «Спиральное обучение» — тема «Функции» появляется в 7, 8, 9 классах с возрастающей глубиной, маршрут строит витки, а не линейную цепочку; «Проектное погружение» — модули из разных предметов группируются вокруг проекта «Экосистема» (биология + математика + химия + география); «От практики к теории» — эксперимент → наблюдение → закономерность → формула, а не наоборот. Родитель/методист выбирает концепцию при построении маршрута; концептуальная онтология пополняется сообществом. Требование не входит в MVP и реализуется на этапе 2.

**Критерии приёмки:**
- (Этап 2) Выбор концепции: при построении маршрута родитель/методист выбирает одну из концепций (или «без концепции»); выбранная концепция сохраняется в параметрах расчёта (0 расчётов без учтённой концепции при её выборе).
- (Этап 2) «Спиральное обучение»: тема с витками глубины появляется в маршруте ≥ 2 раз на разных уровнях сложности с возрастающей глубиной (проверка на контексте основной школы: тема «Функции» — витки в 7, 8, 9 классах); маршрут содержит витки, а не линейную цепочку (0 случаев без витков при выбранной концепции).
- (Этап 2) «Проектное погружение»: модули разных предметов, участвующие в проекте, группируются вокруг проекта; 100% необходимых для проекта модулей присутствуют в маршруте в согласованном порядке (пререквизиты раньше зависимых, 0 нарушений).
- (Этап 2) «От практики к теории»: порядок шагов следует цепочке эксперимент → наблюдение → закономерность → формула — 0 инверсий в маршрутах, построенных с этой концепцией (для тестового набора из ≥10 маршрутов).
- (Этап 2) Эффект концепции: при одинаковых позиции и цели смена концепции меняет порядок/группировку модулей (для эталонного набора из ≥5 сценариев маршруты разных концепций различаются ≥ 1 перестановкой) и не нарушает strict-зависимости (0 нарушений в любом из маршрутов).
- (Этап 1, MVP) Функциональность не предоставляется: маршрут строится без учёта концепции, UI не предлагает выбор концепции (дихотомическая проверка: 0 элементов выбора концепции в MVP-интерфейсе).
