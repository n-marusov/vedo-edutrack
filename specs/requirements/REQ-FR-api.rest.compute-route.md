# REQ-FR-api.rest.compute-route

**Приоритет:** P0
**Ключевая функция:** F6.1
**Источник:** UC-api.rest.compute-route (G2), vision.md F6.1

**Описание:** Сервис должен предоставлять REST API endpoint `GET /routes/compute` для синхронного вычисления образовательной траектории по запросу внешних EdTech-платформ (WebTutor, iSpring, SAP SuccessFactors и др.). Endpoint принимает целевую компетенцию (или набор целей), идентификатор обучающегося и ограничения (максимальная длительность, число модулей) и возвращает упорядоченную последовательность модулей с оценками длительности и связями-пререквизитами. Контракт запроса и ответа должен быть зафиксирован в версионируемой OpenAPI-спецификации.

**Критерии приёмки:**
- Запрос `GET /routes/compute` с параметрами `goal_ids`, `learner_id`, `constraints` (`max_duration_hours`, `max_modules`) возвращает `200 OK` с JSON-схемой `RouteComputationResult` (массив `modules[]` с полями `module_id`, `order`, `duration_hours`, `prerequisites[]`), описанной в OpenAPI-спецификации; невалидные или отсутствующие обязательные параметры возвращают `400 Bad Request` с телом ошибки.
- Медианная латентность ответа не превышает 200 мс при нагрузке 1000 одновременных запросов на эталонном окружении (cross-ref REQ-NFR-api.performance.route-compute-latency).
- При недоступности графа знаний VEDO Hub endpoint возвращает `503 Service Unavailable`; несуществующий `goal_id` или `learner_id` — `404 Not Found`; превышение rate limit — `429 Too Many Requests` с заголовком `Retry-After`; тело ошибок соответствует RFC 7807 (поле `type`, `title`, `detail`).
- Вычисление детерминировано: для одинаковых входных параметров и неизменных данных онтологии результат (состав и порядок модулей) идентичен между последовательными вызовами.
