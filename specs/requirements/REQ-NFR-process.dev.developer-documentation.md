# REQ-NFR-process.dev.developer-documentation

**Приоритет:** P1
**Ключевая функция:** cross-cutting (разработка/передача знаний)
**Источник:** quality-matrix audit ячейка 2.1 (Эргономика/Разработка — документация для разработчика, онбординг команды), развитие REQ-NFR-process.dev.engineering-gates; практика: отсутствие документации разработчика замедляет онбординг и увеличивает bus-factor

**Описание:** Проект обязан иметь документацию разработчика и процедуры передачи знаний: архитектурная документация, навигация по коду, runbook'и, покрытие критичных компонентов несколькими разработчиками — поскольку отсутствие документации замедляет онбординг, увеличивает bus-factor и риск потери знаний. Требование закрывает неучтённый аспект «документация для разработчика и онбординг команды» ячейки 2.1.

**Критерии приёмки:**
- Архитектурная документация: актуальная документация архитектуры (C4/компоненты) покрывает 100% сервисов и ключевых потоков; PR с архитектурным изменением обязан обновлять документацию (гейт в CI).
- Навигация по коду: README каждого модуля/сервиса содержит назначение, структуру, ключевые сценарии; покрытие модулей = 100%.
- Передача знаний: runbook'и и документация покрывают 100% критичных операций (деплой, откат, восстановление) — согласуется с REQ-NFR-process.dev.engineering-gates (поле `runbook_url` у алертов).
- Bus-factor: для каждого критичного компонента ≥ 2 разработчика знакомы с ним (матрица знаний); документация позволяет новому разработчику выполнить онбординг ≤ 1 недели (против ≤ 30 минут окружения из engineering-gates).
- Документация разработчика хранится в репозитории рядом с кодом и проходит код-ревью: 100% обновлений документации — через PR.
