# REQ-FR-api.webhooks.module-mastered

**Приоритет:** P1
**Ключевая функция:** F6.4
**Источник:** UC-api.webhooks.module-mastered

**Описание:** Сервис должен доставлять webhook-событие `module.mastered` подписанным внешним системам (LMS-платформам) в момент подтверждения освоения модуля обучающимся. Событие содержит идентификаторы learner, модуля, траектории и временную метку освоения. Доставка должна быть надёжной (at-least-once): при сбоях выполняются повторные попытки, событие сохраняется в очереди недоставленных (DLQ) после исчерпания попыток, получатель дедуплицирует повторы по `event_id`.

**Критерии приёмки:**
- Событие `module.mastered` публикуется не позднее 60 секунд после подтверждения освоения модуля и доставляется на все зарегистрированные endpoint-ы подписчиков из конфигурации подписки.
- Payload соответствует схеме `ModuleMasteredEvent`: `event_id` (UUID v4), `event_type=module.mastered`, `learner_id`, `module_id`, `plan_id`, `mastered_at` (ISO 8601); валидность payload проверяется schema-тестами для каждого зарегистрированного подписчика.
- При ответе подписчика со статусом, отличным от 2xx, или сетевом сбое доставка повторяется с экспоненциальной задержкой (минимум 5 попыток: 1, 2, 4, 8, 16 минут); после исчерпания попыток событие помещается в DLQ и генерируется алерт в мониторинге.
- Ответ подписчика со статусом 2xx фиксируется как успешная доставка; повторная доставка того же события (одинаковый `event_id`) обрабатывается получателем идемпотентно (см. REQ-FR-api.webhooks.idempotency).
