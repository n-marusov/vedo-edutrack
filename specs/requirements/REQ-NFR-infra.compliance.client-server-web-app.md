# REQ-NFR-infra.compliance.client-server-web-app

**Приоритет:** P0
**Ключевая функция:** cross-cutting (архитектура/форма поставки)
**Источник:** vision.md §1.5 (приложения сервиса: «Дай пять», «Свой Вектор», «Вектор Компетенций» — веб-приложения), specs/c4/README.md (контейнеры «веб-приложение, API-сервер»), решение стейкхолдера (2026-08-02)

**Описание:** Продукт поставляется как **веб-приложение с клиент-серверной архитектурой**: пользовательский интерфейс — веб-клиент (браузер), работающий поверх серверного API; вся предметная логика (маршруты, планы, диагностика лакун, покрытие, покрытие ФГОС) исполняется на сервере. Требование фиксирует форму поставки и границу «клиент ↔ сервер» как базовый архитектурный инвариант, на который опираются C4-диаграммы (уровень Container), ADR `DES.API.communication-patterns` и выбор стека (M0.1).

**Критерии приёмки:**
- Веб-клиент: все пользовательские сценарии (построение маршрута, карта знаний, дашборды, конструктор маршрутов, панель группы) выполняются в браузере через веб-интерфейс без установки клиентского ПО; доступ к сервису — через стандартный HTTPS (проверяется e2e-сценариями MVP в браузере).
- Серверный API: веб-клиент не имеет прямого доступа к данным/BД — все операции идут через серверный API (REST/веб-сокеты); проверка: e2e-тест не находит прямых клиентских вызовов к хранилищам, 100% обращений клиента проходят через API-шлюз/сервер.
- Разделение ответственности: бизнес-логика (вычисление маршрута, лакуны, покрытие) исполняется на сервере, клиент выполняет только отображение и ввод — проверяется инспекцией кода: детерминированное ядро (F1/F2) не содержит клиентского кода, клиентский бандл не содержит алгоритмов ядра.
- Оба контура (Community / Enterprise) используют одну клиент-серверную модель: один веб-клиент, развёртываемый против соответствующего серверного контура (согласуется с REQ-NFR-infra.compliance.community-enterprise-isolation).
- Клиент-серверное взаимодействие отвечает NFR производительности и безопасности: p95 ≤ 200 мс (REQ-NFR-api.performance.latency-p95), JWT RS256 (REQ-NFR-security.compliance.owasp-application-security), поддерживаемые браузеры (REQ-NFR-ui.compliance.supported-browsers).
