# REQ-FR-plan.recalculation.revise-on-delta

**Приоритет:** P1
**Ключевая функция:** F1.9
**Источник:** UC-plan.recalculation.revise-plan-on-delta; vision.md F1.9 (P: «пересчёт плана разрушает обязательство без согласия родителя»)
**Описание:** Пересчёт плана — не автоматический. Условия запуска: наступил новый период, изменена цель, провалена контрольная точка или ручная инициация пользователя. Система пересчитывает маршрут и сравнивает его с зафиксированным планом: если изменение существенное (>15% модулей или >2 недель сдвига плановых дат), формируется дельта «план vs актуальный маршрут» (добавленные, удалённые, изменённые по датам модули, влияние на контрольные точки) и предлагается пересмотр; решение принимает пользователь (принять новый маршрут как план / скорректировать частично / отклонить). Пока новый план не зафиксирован, прогресс измеряется от старого плана, рекомендации — от нового маршрута.

**Критерии приёмки:**
- Корректность дельты: доля изменённых модулей = (|M_route \ M_plan| + |M_plan \ M_route|) / |M_plan| × 100%; дельта показывается тогда и только тогда, когда доля > 15% ИЛИ сдвиг плановых дат > 2 недель — для контрольного набора из ≥30 пар «маршрут/план» 0 ошибок классификации «существенно/несущественно».
- Отсутствие ложных срабатываний: при дельте ≤ 15% модулей и ≤ 2 недель пересмотр не предлагается, план остаётся без изменений, рекомендации обновляются по новому маршруту (0 ложных предложений пересмотра).
- Ворота решения: при существенной дельте фиксация нового плана происходит только после явного решения пользователя — 0 автоматических фиксаций и 0 предложений пересмотра без показа дельты.
- Измерение после отклонения: после отклонения пересмотра прогресс и отклонения (F2.4) измеряются от старого плана, рекомендации — от нового маршрута; система напоминает о доступном пересмотре ≥ 1 раза в 7 дней, пока дельта существенна.
- Провал контрольной точки (A2): дельта формируется вместе с отчётом план-факт (F2.4) и учитывает диагностику лакун (F2.1) — 100% предложений пересмотра после провала содержат оба артефакта.
- Логирование решений: каждое решение пользователя (принять/скорректировать/отклонить) сохраняется с меткой времени и причиной — 0 нелогируемых решений; при отсутствии зафиксированного плана (A4) пересмотр не требуется (0 ошибок).
