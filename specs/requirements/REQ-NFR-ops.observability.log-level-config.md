# REQ-NFR-ops.observability.log-level-config

**Приоритет:** P1
**Ключевая функция:** cross-cutting (операции/observability)
**Источник:** DESCRIPTION.md NFR

**Описание:** Уровень логирования конфигурируется через переменную окружения `LOG_LEVEL` (значения: DEBUG / INFO / WARN / ERROR); логи — структурированные (JSON); ответы об ошибках API — структурированные по единой схеме.

**Критерии приёмки:**
- Конфигурация: старт сервиса с `LOG_LEVEL=DEBUG` выводит debug-события, с `LOG_LEVEL=INFO` — не выводит; с `LOG_LEVEL=ERROR` остаются только error-события; значение вне набора DEBUG/INFO/WARN/ERROR вызывает ошибку конфигурации при старте (exit code ≠ 0) либо fallback на INFO с warning-логом.
- Структурированные логи: каждая запись — JSON с полями `timestamp`, `level`, `service`, `message`, `request_id`, `trace_id`; парсер-валидатор успешно проверяет 100% записей выборки ≥ 1000 строк (валидный JSON, корректный level, формат timestamp ISO 8601).
- Структура ошибок: все ответы 4xx/5xx API соответствуют единой схеме ошибки (`code`, `message`, `request_id`, `details`) — контракт покрыт автоматическим тестом на всех эндпоинтах (0 несоответствий схеме).
- Сквозная трассировка: каждый запрос получает `request_id`, пробрасываемый в логи всех сервисов цепочки; тест цепочки из ≥ 3 сервисных вызовов подтверждает совпадение `request_id` во всех лог-записях.
