# REQ-NFR-ops.performance.scalability

**Приоритет:** P1
**Ключевая функция:** cross-cutting (масштабируемость)
**Источник:** quality-matrix audit ячейки 5.3/3.2 (Тех.обеспеченность/Функции — Сопровождение/Эксплуатация), vision.md G2 («тысячи персональных маршрутов параллельно»), M9 (Enterprise-масштабирование); практика: отказ при пиковой нагрузке в критические окна

**Описание:** Система обязана масштабироваться горизонтально с измеримыми гарантиями под кратный рост нагрузки, поскольку vision G2 требует «тысячи персональных маршрутов параллельно» без деградации, а отказ при пике (окна аттестаций) критичен для бизнеса. Требование закрывает неучтённый аспект «поведение под кратно растущей нагрузкой» ячеек 5.3 и 3.2.

**Критерии приёмки:**
- Нагрузочный тест на кратный рост: система выдерживает 10× пиковую нагрузку относительно базовой (1000 concurrent из REQ-NFR-api.performance.latency-p95) без деградации p95 более чем на 50%.
- Горизонтальное масштабирование: сервисы stateless и масштабируются добавлением нод; автоскейлинг по CPU/очереди: добавление ноды ≤ 5 минут от превышения порога.
- Capacity plan: документированный план ёмкости на рост до 10× текущих пользователей; пересматривается ≥ 1 раза в квартал.
- Деградация при перегрузке: при превышении ёмкости система деградирует предсказуемо (rate limiting, очередь), не теряя данные (0 потерь при перегрузке — согласуется с REQ-NFR-data.availability.write-consistency).
- Пиковые окна: производительность в пиковые окна (аттестации, май) не ниже базовой: p95 ≤ 200 мс при 1000 concurrent (согласуется с REQ-NFR-api.performance.latency-p95).
