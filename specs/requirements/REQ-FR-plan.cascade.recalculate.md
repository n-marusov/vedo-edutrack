# REQ-FR-plan.cascade.recalculate

**Приоритет:** P1
**Ключевая функция:** F1.6
**Источник:** UC-plan.compute.recompute-on-progress; vision.md F1.6, F1.2 (триггеры перестройки)
**Описание:** При изменении маршрута система выполняет каскадный пересчёт зависимых артефактов в фиксированном порядке: маршрут → план обучения на новый период (при зафиксированном плане — «рекомендация vs план», F1.9) → подборка ресурсов (F1.4) → рекомендации проектов и историй (F5.3). Каскад запускается событием `RouteRecalculated` и доставляет обновлённые артефакты подписчикам (GUI через WebSocket/SSE, API через вебхуки). При сбое промежуточного звена завершённые звенья сохраняются, сбойное звено ставится в очередь повторной обработки по расписанию восстановления.

**Критерии приёмки:**
- Полнота: после каждого события `RouteRecalculated` обновляются все 4 звена каскада (маршрут, план, ресурсы, истории/проекты) — для 100% событий зафиксирован результат по каждому звену.
- Порядок: звенья выполняются строго последовательно (маршрут → план → ресурсы → истории/проекты); для выборки из ≥50 событий 0 случаев нарушения порядка.
- Согласованность входов: каждое звено использует результат предыдущего — план строится на новом маршруте, подборка ресурсов — на новом плане, рекомендации — на актуальных ресурсах (0 звеньев, использовавших устаревший вход).
- Устойчивость к сбою: при ошибке звена каскад не останавливает остальные; сбойное звено повторяется по расписанию восстановления (≤ 15 мин) без повторного выполнения завершённых звеньев; итоговое состояние соответствует полному каскаду в течение ≤ 30 мин после события.
- Идемпотентность: повторная доставка того же `RouteRecalculated` не вызывает повторных изменений артефактов (0 дублирующих обновлений при дубле события).
- Распространение: обновлённые артефакты доставляются подписчикам (WebSocket/SSE-клиентам и внешним вебхукам) с указанием версии онтологии расчёта — 100% подписчиков получают обновление в течение ≤ 5 с после завершения каскада.
