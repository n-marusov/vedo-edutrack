# REQ-FR-plan.compute.shortest-path

**Приоритет:** P0
**Ключевая функция:** F1.1
**Источник:** UC-plan.compute.shortest-path-to-goal; vision.md F1.1, P1 («родитель выбирает стратегию из эвристик, а не из расчёта»), P16
**Описание:** Двухэтапное вычисление маршрута от текущей позиции ученика к цели: (1) копирование релевантного подграфа онтологии через REST API VEDO Hub (F0.1, F0.2) — все модули, достижимые из текущей позиции, с их связями и атрибутами; (2) детерминированный алгоритм кратчайшего пути с весами на скопированном подграфе в памяти EduTrack (не на стороне Hub). Учитываются типы связей: `hasStrictPrerequisite` — обязательна, `hasSoftPrerequisite` — опциональна, `enriches` — бонус. Приоритет модуля — функция от статических весов связей и динамического контекста (близость дедлайна, essential-статус, темп ученика, выбранная концепция); конфликт приоритетов разрешается в порядке: essential + strict → soft → enrich. Результат — упорядоченная последовательность шагов (`RouteStep`: модуль + глубина/контекст) с помеченным критическим путём, зафиксированной версией онтологии (для воспроизводимости) и публикацией события `RouteRecalculated` (каскад F1.6).

**Критерии приёмки:**
- Валидность маршрута: для каждого шага маршрута все strict-пререквизиты (`hasStrictPrerequisite`) присутствуют среди освоенных модулей или предыдущих шагов маршрута — доля шагов с нарушением = 0% для любого допустимого входа (позиция, цель, контекст, концепция).
- Оптимальность: среди всех валидных путей от позиции к цели возвращается путь с минимальной суммой весов; для контрольного набора из ≥100 случайных графов (до 5000 модулей, 50 000 связей) результат совпадает с эталонным переборным решением в 100% случаев.
- Воспроизводимость: при неизменных входных данных и фиксированной версии онтологии повторный расчёт даёт идентичную последовательность `RouteStep` (100% совпадение).
- Производительность: время расчёта маршрута (от получения подграфа до готового результата) ≤ 1 с для подграфа ≤ 5000 модулей и ≤ 50 000 связей.
- Конфликты приоритетов разрешаются в порядке essential + strict → soft → enrich: для тестового набора из ≥50 конфликтов 0 случаев, когда модуль с более низким приоритетом вытеснил модуль с более высоким.
- При недостижимости цели по strict-связям (A1) система возвращает список недостающих модулей/связей и предлагает промежуточную цель — пустой ответ без объяснения не допускается (0 случаев).
