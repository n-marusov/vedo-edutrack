# REQ-FR-api.hub.subscribe-updates

**Приоритет:** P1
**Ключевая функция:** F0.3
**Источник:** vision.md F0.3, F1.2 (триггер «обновление онтологии»); этап 2 (MVP исключён — vision 2.5)

**Описание:** Сервис должен подписываться на обновления онтологии VEDO Hub (новые темы, связи, изменения рамок, обновления концепций) через API Hub для каскадного пересчёта маршрутов и планов. Требование этапа 2 (каскадный пересчёт при обновлении онтологии исключён из MVP — vision 2.5, W2); оформляется как FR с пометкой этапа для roadmap M5. Требование закрывает лакуну F0.3 FR-слоя.

**Критерии приёмки:**
- Подписка: сервис получает события обновления онтологии (новые/изменённые темы и связи) через механизм событий Hub (согласуется с REQ-FR-api.webhooks.module-mastered — механизм вебхуков/событий).
- Идемпотентная обработка: повторная доставка события обновления не вызывает повторных изменений (0 дублирующих пересчётов — согласуется с REQ-FR-api.webhooks.idempotency).
- Каскадный пересчёт: после события обновления затронутые маршруты пересчитываются; итоговое состояние соответствует полному каскаду ≤ 30 минут (согласуется с REQ-FR-plan.cascade.recalculate).
- Инкрементальная синхронизация подграфа: после обновления копия подграфа обновляется инкрементально с верификацией версии онтологии (согласуется с REQ-FR-api.hub.copy-subgraph и REQ-NFR-api.availability.hub-dependency-sla).
- Событие обновления не теряется: при сбое обработки событие ставится в очередь повторной обработки (DLQ с алертом, как в REQ-FR-api.webhooks.module-mastered).
