# REQ-NFR-infra.compliance.cicd-supply-chain-security

**Приоритет:** P0
**Ключевая функция:** cross-cutting (разработка)
**Источник:** quality-matrix audit ячейки 4.1/5.1 (Аварии/Разработка, Тех.обеспеченность/Разработка), уроки опыта: tj-actions/changed-files (CVE-2025-30066), SolarWinds, Codecov — компрометация сборочного процесса

**Описание:** Требование закрывает лакуны «Аварии/Разработка» и «Тех. обеспеченность/Разработка» матрицы программирования качества: защита CI/CD-конвейера от supply chain атак — пинирование версий, сканирование секретов, SBOM-генерация.

**Критерии приёмки:**
- Пинирование зависимостей: все зависимости и CI-действия фиксируются точными версиями (lock-файлы, SHA-pinning для действий); запрещены floating-теги (`latest`).
- Сканирование секретов: CI выполняет сканирование на утёкшие секреты (например, gitleaks) — 0 находок как гейт релиза.
- SBOM: для каждого релиза генерируется SBOM (CycloneDX/SPDX) и сохраняется в артефактах релиза.
- Анализ уязвимостей зависимостей: сканирование (например, `npm audit` / OWASP Dependency-Check) — 0 критических и высоких уязвимостей перед релизом.
- Компрометация сборочного процесса: секреты CI не доступны fork-PR (проверка изоляции), многофакторная аутентификация для доступа к CI/CD.
- Воспроизводимость сборки: повторная сборка из зафиксированного коммита даёт идентичный артефакт (детерминированная сборка) — проверяется тестом воспроизводимости.
