# REQ-NFR-data.availability.backup-validity

**Приоритет:** P0
**Ключевая функция:** cross-cutting (данные)
**Источник:** quality-matrix audit ячейки 4.3/5.3 (Аварии/Тех.обеспеченность — Сопровождение), развитие REQ-NFR-data.availability.backup-rpo; урок опыта: GitLab 2017 — из 6 бэкапов восстановились только 5, «валидный» бэкап оказался битым

**Описание:** Бэкап считается валидным только после фактического restore-теста. Каждая резервная копия проверяется восстановлением при создании; перед любой деструктивной операцией на production выполняется обязательная проверка восстановления из свежей копии.

**Критерии приёмки:**
- При создании каждой резервной копии выполняется автоматический restore-тест одного артефакта со сверкой контрольных сумм: расхождение = 0; 100% копий валидны.
- Доля валидных бэкапов в репозитории: 100% (0 копий с нарушенной целостностью).
- Перед любой деструктивной операцией на production (удаление данных, массовое изменение) выполняется restore smoke-test из копии возрастом ≤ 1 часа: успешное восстановление + сверка целостности (расхождение = 0); результат фиксируется в чек-листе операции.
- Если restore-тест не пройден — деструктивная операция блокируется автоматически.
