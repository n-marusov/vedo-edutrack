# REQ-FR-plan.compute.essential-core

**Приоритет:** P0
**Ключевая функция:** F1.1.4
**Источник:** UC-plan.compute.filter-by-essential-core; vision.md F1.1 (приоритет модуля — essential-статус), F1.1.4 (P: «школьная программа должна быть закрыта независимо от цели»)
**Описание:** Essential-ядро — множество обязательных модулей для контекста обучения (школьная программа / роль / онбординг), загружаемое из онтологии (F0.1). В контексте «школьное образование» модули ядра всегда присутствуют в маршруте и критическом пути независимо от того, лежат ли они на кратчайшем пути к цели: порядок и темп прохождения вариативны, логика strict-зависимостей нерушима. При конфликте приоритетов применяется порядок: essential + strict → soft → enrich. Модули ядра, закрывающие ФГОС-дефициты, дополнительно получают повышенный приоритет за N недель до аттестации (F1.12). Маршрут публикуется с пометками essential, результат воспроизводим на той же версии онтологии.

**Критерии приёмки:**
- Полнота ядра: для контекста «школьное образование» каждый модуль essential-ядра включён в маршрут и в критический путь — доля пропущенных модулей ядра = 0% при любых входных данных (цель, позиция, темп, концепция).
- Нерушимость зависимостей: для каждого модуля ядра все его strict-пререквизиты стоят ранее в маршруте (0 нарушений порядка strict-связей, включая связи с модулями вне ядра).
- Вариативность порядка: при разных целях/темпах порядок необязательных (soft/enrich) модулей и темп прохождения ядра могут различаться, но состав ядра в маршруте неизменен; атрибут essential присвоен 100% модулей ядра в публикуемом маршруте.
- Приоритетность: при конфликте приоритетов модуль essential+strict всегда получает приоритет над soft и enrich — для тестового набора из ≥50 конфликтов 0 случаев, когда soft/enrich вытеснил essential+strict.
- Конфликт ядра с целью (A1): если цель (углублённая специализация) несовместима с ядром по составу, ядро сохраняется, цель помечается как достижимая с расширенным составом, пользователь уведомляется о длительности (0 молчаливых исключений модулей ядра).
- Ядро не определено (A2): при отсутствии essential-ядра в онтологии маршрут строится без ограничения ядра, атрибут essential отсутствует, расчёт завершается без ошибок (0 сбоев).
- Длительность (A4): если включение ядра превышает доступное время до цели, система предлагает ≥ 1 альтернативу (интенсификация, сокращение необязательных модулей) и передаёт решение пользователю.
