# REQ-NFR-api.availability.webhook-idempotency

**Приоритет:** P0
**Ключевая функция:** F6.4 (интеграция через webhooks)
**Источник:** README.md (требования), vision.md (F6.4)

**Описание:** Обработка входящих webhook-событий (изменения онтологии в VEDO Hub, события пользователей) должна быть идемпотентной: повторная доставка одного и того же события не нарушает состояние системы — дубликаты не приводят к дублированию данных или ошибкам обработки.

**Критерии приёмки:**
- Каждое событие имеет уникальный dedup-ключ (например, `<source>:<event_id>`); повторная обработка события с уже обработанным ключом не меняет состояние и возвращает ответ-подтверждение (HTTP 200 с признаком `duplicate`).
- Тест replay: отправка одного и того же события 2 раза подряд приводит к идентичному конечному состоянию БД — сравнение снапшотов состояния до/после второго вызова показывает 0 изменений.
- Тест конкурентной доставки: 2 параллельных запроса с одинаковым dedup-ключом → в БД создаётся ровно одна запись (проверяется уникальным constraint на ключ).
- Прогон теста из ≥ 1000 событий, включая 10% намеренных дубликатов: доля потерянных или дважды применённых событий = 0; обработчик выдерживает повторную доставку после сбоя/рестарта сервиса (состояние идемпотентности переживает рестарт).
