# REQ-NFR-data.compliance.decommissioning-safety

**Приоритет:** P1
**Ключевая функция:** cross-cutting (вывод из эксплуатации/миграция)
**Источник:** quality-matrix audit ячейки 1.4/2.4/4.4 (Среда/Эргономика/Аварии — Вывод из эксплуатации), развитие REQ-NFR-data.compliance.service-decommissioning и REQ-NFR-data.compliance.pii-export-deletion; практика миграций: частичная миграция приводит к потере данных

**Описание:** Система обязана обеспечивать безопасность аварийных сценариев вывода из эксплуатации и миграции: частичная миграция, потеря данных при сбое, зависшие транзакции — с измеримыми гарантиями целостности и эргономичным интерфейсом администратора (консоль отслеживания шагов вывода).

**Критерии приёмки:**
- При сбое миграции система переходит в консистентное состояние: частично мигрированные данные не теряются (транзакционная миграция или восстановимая контрольная точка); потеря данных при сбое миграции = 0.
- Зависшие транзакции при миграции/деактивации разрешаются автоматически: 100% зависших операций завершаются или откатываются ≤ 24 часов; пользователь видит статус операции (согласуется с REQ-NFR-data.compliance.pii-export-deletion).
- UX администратора при деактивации: консоль администратора отображает статус каждого шага вывода (уведомление, экспорт, отзыв доступов, архивирование) с индикатором прогресса; 100% шагов отслеживаемы.
- Тест устойчивости: симуляция сбоя миграции (обрыв на 50% данных) → целостность данных = 100% (расхождение контрольных сумм = 0); повторный запуск миграции с контрольной точки успешен.
- Процедура согласуется с чек-листом вывода из эксплуатации из REQ-NFR-data.compliance.service-decommissioning (не дублирует, а дополняет аварийными сценариями).
