# REQ-NFR-infra.compliance.oss-licensing

**Приоритет:** P1
**Ключевая функция:** cross-cutting (инфраструктура/разработка)
**Источник:** quality-matrix audit ячейки 1.1/5.1 (Среда/Тех.обеспеченность — Разработка); практика управления open-source-зависимостями

**Описание:** Использование open-source-компонентов регулируется политикой лицензий: разрешены пермиссивные лицензии, copyleft запрещён для библиотек и распространяемого кода, проверка лицензий автоматизирована в CI. Исходный код хранится в корпоративном VCS с RBAC. Требование закрывает лакуну «Среда/Разработка» (ячейка 1.1): ограничения среды на процесс создания.

**Критерии приёмки:**
- Политика лицензий: разрешены MIT, Apache-2.0, BSD-2/3; запрещены GPL/AGPL для компонентов, включаемых в распространяемый код; LGPL — по письменному согласованию.
- CI-скан лицензий (license-checker / FOSSA / «Контур.Ориго» или эквивалент): 0 нарушений политики = гейт релиза.
- Лицензия каждой зависимости присутствует в SBOM (CycloneDX/SPDX, см. REQ-NFR-infra.compliance.cicd-supply-chain-security).
- Исходный код хранится в корпоративном VCS (self-hosted для Enterprise-контура), доступ по RBAC, write-доступ — с MFA: 0 прямых анонимных write-операций.
