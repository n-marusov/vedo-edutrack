# REQ-NFR-infra.availability.multi-az-geo-dr

**Приоритет:** P2
**Ключевая функция:** cross-cutting (инфраструктура)
**Источник:** quality-matrix audit ячейки 1.2 (Среда/Эксплуатация); урок опыта: AWS S3 outage 2017 — отказ единственного региона парализовал зависимые сервисы

**Описание:** Инфраструктура сервиса разворачивается в нескольких зонах доступности (multi-AZ, ≥ 2 зоны) для данных и сервиса. Георезервирование (второй регион) — требование Enterprise-контура (M9), а не MVP, при условии достижимости RTO ≤ 4 ч из бэкапов. Требование закрывает неучтённый аспект «природные/геораспределённость» ячейки 1.2.

**Критерии приёмки:**
- Сервис и данные развёрнуты в ≥ 2 зонах доступности: выход из строя одной зоны не приводит к недоступности (проверяется fault-injection-тестом ≥ 1 раза в квартал).
- Выход из строя одной зоны не нарушает RPO ≤ 1 ч и RTO ≤ 4 ч (согласовано с REQ-NFR-data.availability.backup-rpo).
- Георезервирование (второй регион/DR-центр) — требование Enterprise-контура: при развёртывании Enterprise задаётся стратегия DR (активный/пассивный, целевые RTO/RPO).
- Офлайн-кэш подграфа 24 ч (REQ-NFR-api.availability.hub-dependency-sla) сохраняется при отказе зоны: проверка в fault-injection-тесте.
