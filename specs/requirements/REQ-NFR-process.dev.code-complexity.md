# REQ-NFR-process.dev.code-complexity

**Приоритет:** P1
**Ключевая функция:** cross-cutting (разработка/качество кода)
**Источник:** quality-matrix audit ячейка 2.1 (Эргономика/Разработка — когнитивная нагрузка кода), развитие REQ-NFR-process.dev.engineering-gates; практика: высокая цикломатическая сложность коррелирует с дефектностью и замедляет ревью

**Описание:** Код обязан соответствовать лимитам когнитивной сложности: цикломатическая сложность, размер функций, глубина вложенности — поскольку высокая сложность увеличивает дефектность и замедляет код-ревью. Требование углубляет ячейку 2.1 (Эргономика/Разработка) с 🟡 до 🟢.

**Критерии приёмки:**
- Цикломатическая сложность: CC ≤ 10 для 100% функций (гейт в CI); функции с CC > 15 требуют рефакторинга до merge.
- Размер функций: 100% функций ≤ 60 строк (или эквивалент для выбранного языка); превышение — ревью-гейт.
- Глубина вложенности: ≤ 4 уровня для 100% кода (гейт в CI).
- Метрики сложности публикуются в отчёте CI; регрессия сложности (рост средней CC) > 10% между релизами блокирует релиз.
- Согласуется с REQ-NFR-process.dev.engineering-gates: метрики сложности добавляются к существующим гейтам (линтеры, ревью).
