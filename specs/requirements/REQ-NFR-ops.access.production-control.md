# REQ-NFR-ops.access.production-control

**Приоритет:** P0
**Ключевая функция:** cross-cutting (безопасность/операции)
**Источник:** quality-matrix audit ячейки 1.3/4.3 (Среда/Аварии — Сопровождение); уроки опыта: GitLab 2017 — удаление production-БД одним оператором, Okta 2022 — компрометация административных учётных записей поддержки

**Описание:** Доступ к production-окружению контролируется: деструктивные операции выполняются по правилу «двух пар глаз» (2-person rule) с JIT-выдачей прав ограниченного срока, все административные действия аудируются, заданы целевые MTTA/MTTR для P1-инцидентов. Требование закрывает лакуну «Среда/Сопровождение» (ячейка 1.3): регуляторные и корпоративные условия сопровождения.

**Критерии приёмки:**
- Деструктивные операции на production (удаление, массовые изменения, смена конфигурации) выполняются только по 2-person rule: 100% таких операций подтверждены вторым оператором.
- Привилегированный доступ выдаётся JIT (just-in-time) с TTL ≤ 4 часов; после TTL доступ автоматически отзывается.
- 100% административных действий фиксируются в аудит-логе (кто, что, когда, с какого IP); аудит-лог неизменяемый (append-only).
- Разработчики имеют read-only доступ к production (логи/метрики); изменения — только через CI/CD: 0 прямых write-операций разработчиков.
- MTTA для P1 ≤ 15 минут, MTTR для P1 ≤ 4 часов (согласовано с RTO из REQ-NFR-data.availability.backup-rpo); измеряется по тикетам инцидентов ежемесячно.
