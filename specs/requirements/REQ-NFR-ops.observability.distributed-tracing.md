# REQ-NFR-ops.observability.distributed-tracing

**Приоритет:** P1
**Ключевая функция:** cross-cutting (операции/observability)
**Источник:** quality-matrix audit ячейка 3.3 (Функции/Сопровождение — распределённая трассировка), развитие REQ-NFR-ops.observability.log-level-config; практика SRE (OpenTelemetry)

**Описание:** Система обязана поддерживать end-to-end распределённую трассировку поверх существующего request_id, чтобы диагностировать распределённые инциденты (вызов Hub API → движок маршрутов → БД → webhook-доставка). Экспорт трасс в tracing-бэкенд (OpenTelemetry/Jaeger) с гарантированным покрытием.

**Критерии приёмки:**
- Каждый входящий запрос получает trace_id (совместим с request_id из REQ-NFR-ops.observability.log-level-config); trace_id пробрасывается во все вызовы цепочки (тест цепочки из ≥ 3 сервисных вызовов: совпадение trace_id = 100%).
- Span'ы создаются для: вызовов VEDO Hub API, SPARQL-запросов, обращений к БД, исходящих webhook-доставок; покрытие = 100% этих типов вызовов.
- Экспорт трасс в tracing-бэкенд (OTLP/Jaeger): 100% трасс, содержащих ошибки, и ≥ 10% успешных (sampling rate); потери трасс = 0 для ошибочных запросов.
- Время от завершения запроса до доступности полной трассы в UI: p95 ≤ 5 минут.
- Распределённая трассировка покрывает те же сервисы, что и метрики из REQ-NFR-api.performance.latency-p95 (покрытие = 100% сервисов).
