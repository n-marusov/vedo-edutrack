# REQ-NFR-process.dev.engineering-gates

**Приоритет:** P0
**Ключевая функция:** cross-cutting (разработка)
**Источник:** quality-matrix audit ячейки 2.1/3.1/5.1 (Эргономика/Функции/Тех.обеспеченность — Разработка); практика инженерных гейтов качества

**Описание:** Процесс разработки обязан иметь автоматические гейты качества: линтеры, форматтер, обязательное код-ревью и покрытие критичных алертов runbook'ами — чтобы в main не попадал код, не прошедший проверки, а любой алерт сопровождался инструкцией по реагированию. Требование закрывает лакуну «Эргономика/Разработка» (ячейка 2.1): эргономика инструментов и процессов команды разработки.

**Критерии приёмки:**
- Линтер в CI: 0 ошибок (errors) на merge в main; warnings не блокируют, но фиксируются в отчёте.
- Форматтер: format-check в CI с 0 расхождений.
- Код-ревью: 100% изменений проходят ревью с ≥ 1 approve до merge; время от открытия PR до первого ревью ≤ 24 часов (p95).
- Runbook'и: 100% критичных алертов (P1/P2) имеют runbook — проверка автоматическая: поле `runbook_url` обязательно в конфигурации алерта; 0 алертов P1/P2 без runbook.
- Онбординг: окружение разработчика поднимается одной командой (`make up` или эквивалент) ≤ 30 минут по инструкции README; проверка — onboarding-сессия нового разработчика.
