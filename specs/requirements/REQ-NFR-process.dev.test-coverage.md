# REQ-NFR-process.dev.test-coverage

**Приоритет:** P1
**Ключевая функция:** cross-cutting (разработка)
**Источник:** quality-matrix audit ячейки 3.1 (Функции/Разработка), тест-пирамида (Mike Cohn); урок опыта: Knight Capital 2012 — дефект переиспользованного флага не был покрыт e2e-проверкой

**Описание:** Заданы целевые уровни покрытия тестами по пирамиде: unit, integration, e2e. Алгоритмическое ядро (движок маршрутов F1, диагностика лакун F2) покрывается с повышенным приоритетом, критичные сценарии MVP — e2e-тестами.

**Критерии приёмки:**
- Line coverage unit-тестами: ядро маршрутов (F1) и диагностики лакун (F2) ≥ 90%; остальной код ≥ 80% (измеряется в CI, отчёт в каждом релизе).
- Integration-тесты покрывают ≥ 70% контрактов публичного API и SPARQL-слой.
- e2e-тесты покрывают 100% Must-критериев MVP из `specs/requirements/MVP-ACCEPTANCE-CRITERIA.md` (M1–M10): 10 сценариев.
- Mutation testing (Stryker/PIT или эквивалент) для ядра F1/F2: выживаемость мутантов ≤ 15%.
- Снижение покрытия относительно предыдущего релиза = 0 (регрессия запрещена).
