# REQ-NFR-infra.compliance.community-enterprise-isolation

**Приоритет:** P0
**Ключевая функция:** cross-cutting (Enterprise-контур)
**Источник:** DESCRIPTION.md NFR, vision.md (2.9)

**Описание:** Контуры Community (публичное облако) и Enterprise (on-premise / private cloud) полностью изолированы: данные одного контура недоступны из другого, прямой кросс-контурный доступ к данным отсутствует, в том числе при подмене идентификаторов ресурсов.

**Критерии приёмки:**
- Тест изоляции данных: все API-запросы пользователя Community-контура к ресурсам Enterprise-контура (включая запросы с подменёнными id) возвращают 403/404; обратная проверка (Enterprise → Community) — аналогично; 100% кросс-контурных попыток отклоняется.
- Сетевая сегментация: между контурами отсутствует прямой сетевой путь — firewall-правила/security groups запрещают соединения Community → Enterprise (кроме явно разрешённых сервисных маршрутов); сетевой скан показывает 0 открытых портов между контурами.
- Хранилища (БД, объектные бакеты, кеши) контуров разделены (разные tenant/namespace/учётные записи/физические серверы); аудит доступа к хранилищам за отчётный период показывает 0 кросс-контурных операций чтения/записи.
- Enterprise-контур развёртывается on-premise или в private cloud с выделенными ресурсами; CI/CD-пайплайн использует отдельные credentials и secrets для каждого контура (отсутствие общих секретов — проверка сканером секретов = 0 совпадений).
