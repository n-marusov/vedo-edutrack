# REQ-FR-api.webhooks.idempotency

**Приоритет:** P0
**Ключевая функция:** F6.4
**Источник:** README requirements — cross-ref REQ-NFR-api.availability.webhook-idempotency

**Описание:** Обработка webhook-событий на стороне получателя должна быть идемпотентной: повторная доставка одного и того же события (следствие гарантии at-least-once) не должна изменять состояние системы, приводить к двойному начислению прогресса или дублированию записей. Идемпотентность обеспечивается ключом дедупликации `event_id`, уникальность которого гарантируется на уровне хранилища.

**Критерии приёмки:**
- Каждое событие содержит уникальный `event_id` (UUID v4), который не изменяется при повторных попытках доставки одного и того же события.
- Обработчик, получивший событие с уже обработанным `event_id`, пропускает бизнес-логику и возвращает `200 OK` с признаком `duplicate=true`, не изменяя состояние (подтверждается тестом двойной последовательной доставки).
- Повторная доставка события (одинаковый payload и `event_id`) не создаёт дубликатов: количество записей в таблицах `events` и `progress_log` не увеличивается после повторного применения (проверяется интеграционным тестом).
- Две конкурентные доставки одного и того же события (parallel delivery) приводят ровно к одному применению бизнес-логики: уникальный constraint на `event_id` в БД отклоняет второй insert, итоговое состояние соответствует однократной обработке.
