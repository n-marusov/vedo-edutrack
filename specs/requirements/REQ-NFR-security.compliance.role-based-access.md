# REQ-NFR-security.compliance.role-based-access

**Приоритет:** P0
**Ключевая функция:** cross-cutting (авторизация)
**Источник:** DESCRIPTION.md NFR, vision.md (3.1)

**Описание:** Доступ к данным и функциям платформы управляется RBAC на **универсальной модели архетипов** (ADR T5): роль — экземпляр архетипа (данные каталога). Каталог EduTrack обязан содержать сид-роли, покрывающие персон vision.md §3.1: learner (`self`), parent (`dependents-owner`), school-director (`management`), methodologist (`management`), hr-manager (`management`). Область видимости определяется ролью (архетипом) и правилами scope: родитель — только собственные дети; директор — только своя школа; HR — только свой департамент. Проверка роли и scope выполняется на серверной стороне, а не только на UI.

**Критерии приёмки:**
- Ролевая матрица (архетип × ресурс × действие, материализуется в роли-экземпляры) задокументирована и реализована; каждая операция API проверяет одновременно роль (архетип) и scope (отказ — HTTP 403; для несуществующих ресурсов — 404 без раскрытия информации).
- Тест enforcement: для каждой из 5 обязательных сид-ролей (экземпляров архетипов `self`/`dependents-owner`/`management`) выполняется набор позитивных (доступ разрешён) и негативных (доступ запрещён) проверок; матрица тестов покрывает 100% ячеек архетип × ресурс, все негативные проверки завершаются запретом без исключений.
- Тест обхода scope: parent (архетип `dependents-owner`) не получает данные чужих детей, director/hr-manager (архетип `management`) — данные чужой школы/департамента (прямые API-вызовы с чужим resource id → 403/404); 100% попыток обхода отклоняется.
- Изменение роли, увольнение или перевод отражаются на правах доступа в течение ≤ 15 минут (TTL кеша прав) без перезапуска сервиса; тест проверяет фактическое время между изменением роли и применением запрета.
