# REQ-NFR-security.compliance.role-based-access

**Приоритет:** P0
**Ключевая функция:** cross-cutting (авторизация)
**Источник:** DESCRIPTION.md NFR, vision.md (3.1)

**Описание:** Доступ к данным и функциям платформы управляется ролями (RBAC): learner (обучающийся), parent (родитель), school director (директор школы), methodologist (методист), HR (кадровый специалист). Область видимости определяется ролью и правилами scope: родитель — только собственные дети; директор — только своя школа; HR — только свой департамент. Проверка роли и scope выполняется на серверной стороне, а не только на UI.

**Критерии приёмки:**
- Ролевая матрица (роль × ресурс × действие) задокументирована и реализована; каждая операция API проверяет одновременно роль и scope (отказ — HTTP 403; для несуществующих ресурсов — 404 без раскрытия информации).
- Тест enforcement: для каждой из 5 ролей выполняется набор позитивных (доступ разрешён) и негативных (доступ запрещён) проверок; матрица тестов покрывает 100% ячеек роль × ресурс, все негативные проверки завершаются запретом без исключений.
- Тест обхода scope: parent не получает данные чужих детей, director — данные чужой школы, HR — данные чужого департамента (прямые API-вызовы с чужим resource id → 403/404); 100% попыток обхода отклоняется.
- Изменение роли, увольнение или перевод отражаются на правах доступа в течение ≤ 15 минут (TTL кеша прав) без перезапуска сервиса; тест проверяет фактическое время между изменением роли и применением запрета.
