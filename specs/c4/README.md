# C4-диаграммы — VEDO EduTrack

В этой директории хранятся архитектурные диаграммы проекта VEDO EduTrack в нотации C4. Диаграммы описывают сервис образовательных маршрутов на базе VEDO Hub на трёх уровнях детализации.

## Уровни C4

| Уровень | Назначение | Аудитория |
|---------|-----------|-----------|
| **1. System Context** | Система и её внешние акторы: VEDO Hub, ученики, родители, HR, методисты, EdTech-платформы, LMS | Бизнес, продукт |
| **2. Container** | Крупные строительные блоки: веб-приложение, API-сервер, движок маршрутов, PostgreSQL, кэш | Архитекторы, разработчики |
| **3. Component** | Компоненты внутри контейнеров: планирование маршрута, исполнение плана, диагностика лакун, визуализация, порт онтологии | Разработчики |
| *(4. Code — не используется)* | | |

## Правила именования файлов

Файлы именуются по шаблону `<LEVEL>-<name>.md`, где:

- `LEVEL` = `context` | `container` | `component`
- `name` — короткая англоязычная метка в kebab-case

### Примеры

| Файл | Описание |
|------|----------|
| `context-system.md` | System Context: EduTrack и внешние системы |
| `container-overview.md` | Container: общий обзор контейнеров |
| `container-api-server.md` | Container: детальный вид API-сервера |
| `component-route-engine.md` | Component: движок планирования маршрута |
| `component-execution.md` | Component: модуль исполнения плана |

## Формат описания

Каждый файл диаграммы содержит:

- **Mermaid-диаграмму** в блоке ` ```mermaid `
- **Легенду** — описание узлов и связей
- **Контекст** — для какого сценария построена диаграмма
- **Связи с функциями** — ссылки на F1–F6 из `vision.md`

## Специфика EduTrack

- **VEDO Hub — внешняя система**: на всех уровнях VEDO Hub изображается как внешний контейнер, не как часть EduTrack. EduTrack читает онтологию через API/MCP Hub.
- **Два контура**: Community (публичная онтология, families, EdTech) и Enterprise (корпоративная, изолированная). На уровне System Context оба контура — разные экземпляры одной системы с разными акторами.
- **Маршрут — вычисление, не хранение**: маршрут не изображается как хранилище данных; он вычисляется на лету и кэшируется.
