## 2. Ответ (Best-Practice Answers)

### A1. F0.1 — Чтение онтологии (критично)

**Ответ:** Сервис обязан читать онтологию VEDO Hub через REST API и MCP-сервер (read-only): модули, 5 типов связей, ФГОС-привязки, ресурсы, истории, концепции — с измеримыми гарантиями полноты, таймаутов и версионирования.

**Критерии:** контракт чтения через OpenAPI; таймауты ≤ 3 с (согласуется с hub-dependency-sla); полнота выборки = 100% запрошенных сущностей; версия онтологии фиксируется.

### A2. F0.2 — Копирование подграфа (критично)

**Ответ:** Сервис обязан копировать релевантный подграф (модули, достижимые из позиции ученика, с связями и атрибутами) в память для вычислений, с измеримыми гарантиями полноты и консистентности копии.

**Критерии:** подграф включает 100% модулей, достижимых из позиции; копия консистентна (связи не ссылаются на отсутствующие узлы = 0); время копирования ≤ 5 с для онтологии ≤ 10 000 модулей.

### A3. F0.3 — Подписка на обновления (этап 2)

**Ответ:** Сервис обязан подписываться на обновления онтологии (новые темы, связи, изменения рамок) через API Hub для каскадного пересчёта — требование этапа 2, оформляется как FR с явной пометкой «этап 2».

**Критерии:** доставка событий обновления (см. webhooks); идемпотентная обработка; каскадный пересчёт ≤ 30 мин (согласуется с cascade.recalculate).

### A4. F6.3 — LMS-коннекторы (этап 2)

**Ответ:** Сервис обязан предоставлять готовые коннекторы к LMS (WebTutor, iSpring, SAP SuccessFactors): двусторонний обмен маршрут/прогресс — требование этапа 2 (M6), оформляется с измеримыми критериями.

**Критерии:** коннекторы для 3 LMS; двусторонняя синхронизация; идемпотентность; обработка ошибок LMS.
