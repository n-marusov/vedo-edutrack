# Undocumented Hub env vars + stale TODO comment from /aif-verify findings

**Date:** 2026-08-03 18:59
**Files:** deploy/.env.example, backend/internal/modules/ontologyport/adapters/adapters.go, backend/internal/platform/config/config_test.go
**Severity:** low

## Problem

`/aif-verify` (normal mode) after the M1 implementation flagged two non-blocking documentation findings:

1. **New env vars undocumented** — `VEDO_HUB_GRAPHQL_PATH` and `VEDO_HUB_BEARER_TOKEN` were introduced in `backend/internal/platform/config/config.go` (T3 Hub GraphQL client), but `deploy/.env.example` documented only `VEDO_HUB_API_URL`. Anyone configuring a Hub connection had no reference for the new knobs.
2. **Stale TODO comment** — `backend/internal/modules/ontologyport/adapters/adapters.go` still carried `// TODO: replaced by real VEDO Hub GraphQL client in M1.` from the M0.3 scaffold era, even though the real client landed in `adapters/hub` (T3, M1).

## Root Cause

- **Missing documentation:** the Hub client config fields were added to the `Config` struct and `Load()` (with `envOrDefault`), but the env documentation file (`.env.example`) and the config itself were updated in the same change — the writer updated code but not the reference docs. This is the classic "code updated, docs not" drift.
- **Stale TODO:** the scaffold-era placeholder comment in the `adapters` package doc was never revisited when the actual client was implemented in the sibling `adapters/hub` package. TODO comments that reference "future" work become misleading once the work is done — they must be removed or rewritten at implementation time.

## Solution

1. `deploy/.env.example` — added two commented lines under "Dynamic runtime config":
   - `VEDO_HUB_GRAPHQL_PATH=/graphql` (default note)
   - `VEDO_HUB_BEARER_TOKEN=` (empty = no auth)
2. `backend/internal/modules/ontologyport/adapters/adapters.go` — replaced the stale TODO with a package doc pointing to `adapters/hub` (real client, T3) and `adapters/stub` (dev/test tooling).
3. `backend/internal/platform/config/config_test.go` (new) — added `TestLoadHubGraphQLSettings` (custom values parsed) and `TestLoadHubGraphQLDefaults` (defaults `/graphql` and empty token) to lock the env contract.

## Prevention

- When adding a new env var in `config.go`, update `deploy/.env.example` in the same change — the two files are one contract.
- When a scaffold TODO references work that is now done, remove/replace the TODO in the implementation task that completes it (the `ontologyport/adapters/adapters.go` comment should have been touched in T3).
- `/aif-verify` already checks env vars vs `.env.example` (Step 3.3) — run it before handoff; add a config unit test whenever a new config field is introduced.
