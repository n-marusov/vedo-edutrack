# Fix: frontend typecheck, biome CSS formatting, secrets-check and Docker backend DNS

**Date:** 2026-08-04 22:23
**Files:** frontend/src/pages/Landing.tsx, frontend/src/styles/pixso-variables.css, deploy/ci/secrets-check.sh, deploy/backend.Dockerfile (new), deploy/docker-compose.yml
**Severity:** medium

## Problem

Three fast-tier CI gates were failing and the Docker Compose backend container exited immediately:

1. **ts-typecheck** – `src/pages/Landing.tsx`: 18 TS2322 errors — `id`, `className`, and Pixso slot props (`slot_4_273`, `slot_4_258`, `slot_7_208`, `slot_7_211`, `slot_7_212`) passed to components whose prop types did not accept them.
2. **biome-check** – `pixso-variables.css` had CRLF line endings and was not formatted by Biome.
3. **secrets-check** – false positives on `docs/integration/examples/` (curl TOKEN var default and Python placeholder webhook secret).
4. **Docker backend container** exited with code 1 — `go install github.com/air-verse/air@latest` failed because Docker DNS on Windows (`127.0.0.11:53`) could not resolve `proxy.golang.org` or `sum.golang.org`.

## Root Cause

1. Pixso design export generates components with `id`, `className`, and named slot props (`slot_<nodeId>`) but the hand-written wrapper components (`CTAButton`, `Eyebrow`, `SectionHeader`) only declared `children` and/or descriptive props.
2. Biome enforces LF line endings and specific formatting; the Pixso-generated CSS was committed with CRLF and no Biome pass.
3. The secrets-check grep pattern matched `TOKEN="${TOKEN:-}"` (bash var default) and `secret = "0123456789..."` (placeholder) in documentation examples.
4. The docker-compose.yml used `image: golang:1.26-alpine` directly with `command: sh -c "go install github.com/air-verse/air@latest && air -c .air.toml"`. This requires DNS resolution of `proxy.golang.org` and `sum.golang.org` at EVERY container startup. On Windows Docker Desktop, the embedded DNS resolver (`127.0.0.11`) often cannot resolve these hosts due to VPN, corporate proxy, or Hyper-V virtual switch interference — a well-known Windows Docker issue.

## Solution

1. **Landing.tsx:** Extended prop interfaces for `CTAButton`, `Eyebrow`, and `SectionHeader` to accept `id?: string`, `className?: string`, and the expected `slot_*` props. Passed `id` and `className` through to the root `<div>` of each component. Fixed a missing closing `>` on a JSX tag that was introduced during the edit.
2. **pixso-variables.css:** Ran `biome format --write` to normalize formatting and line endings.
3. **secrets-check.sh:** Added `:!docs/integration/examples/` to the `git grep` exclusion pattern for hardcoded credential checks.
4. **Docker fix (long-term):** Created `deploy/backend.Dockerfile` — a dedicated dev image extending `golang:1.26-alpine` with `github.com/air-verse/air@v1.67.4` pre-installed at BUILD time. Updated `deploy/docker-compose.yml` to use `build:` pointing to this Dockerfile with `command: ["air", "-c", ".air.toml"]`. The image builds once (build cache persists), and the `go install` step never runs at container startup. This completely eliminates the DNS dependency from the runtime path.

## Prevention

- When adding Pixso-exported components, always include `id`, `className`, and known slot props in the interface.
- Run the fast-tier gates (`bash deploy/ci/run-gates.sh --tier fast`) locally before pushing.
- CI `secrets-check` already excludes docs directories; `docs/integration/examples/` is now part of that exclusion.
- **Dev container pattern:** Tools needed only for development (`air`, `mockgen`, etc.) should be pre-installed in a dev-specific Dockerfile at build time, never via `go install` at container startup. This avoids DNS and network dependencies from the runtime path and speeds up container restarts.
- Pinned versions (`@v1.67.4`) ensure deterministic builds in CI.
