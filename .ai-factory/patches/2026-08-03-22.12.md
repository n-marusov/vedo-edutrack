# Frontend API contract mismatch in visualization feature

**Date:** 2026-08-03 22:12
**Files:** frontend/src/features/visualization/api.ts, frontend/src/features/visualization/__tests__/visualization.test.tsx
**Severity:** medium

## Problem

`fetchProgress()` in the visualization API layer expected
`{ progress: Record<string, ModuleStatus> }`, but the backend endpoint
`GET /learners/{learner_id}/progress` returns
`{ learner_id, modules: ModuleProgressItem[] }`. When wired to the real API,
every module would map to `undefined` and the knowledge map would not
color-code. Additionally, `fetchGraphData()` called
`GET /api/v1/visualization/graph`, an endpoint that does not exist in the
OpenAPI spec (404 at runtime).

Found by `/aif-review` (frontend/backend contract drift).

## Root Cause

The visualization API layer was written against an assumed response shape
instead of the actual OpenAPI contract. Two failure modes combined:

1. The frontend `ProgressResponse` type was invented (`{ progress: {...} }`)
   rather than mirrored from `backend/api/openapi/v1.yaml` where the real
   schema is `ProgressResponse { learner_id, modules[] }`.
2. `fetchGraphData()` referenced a route that was never added to the spec —
   the graph is assembled from ontology concepts, not served as a single
   endpoint.

The OpenAPI spec is the single source of truth for API contracts
(ADR-DES.API.communication-patterns, OpenAPI-first); the frontend types must
mirror it, not approximate it.

## Solution

1. `ProgressResponse` now mirrors the OpenAPI schema exactly
   (`learner_id`, optional `plan_id`/`generated_at`, `modules`).
2. Added `toStatusMap()` — a pure function converting `modules[]` to
   `Record<string, ModuleStatus>` (mapping `not_started`/`skipped` →
   `available`, `in_progress` → `in-progress`, `mastered` → `mastered`).
   Color-coding consumers call this instead of assuming the API shape.
3. Replaced `fetchGraphData()` (dead endpoint) with `buildGraph(moduleIds)`
   that assembles nodes/edges from the existing ontology-port `getConcept()`
   — the graph is a projection of ontology reads, not a bespoke endpoint.
4. Added 3 unit tests for `toStatusMap` covering the status mapping and the
   empty input case.

## Prevention

- Frontend API types MUST be copied from the OpenAPI spec schemas
  (`backend/api/openapi/v1.yaml`), not invented. Any conversion between API
  shape and component shape belongs in a pure helper with unit tests.
- Before adding a `fetch*` function, verify the route exists in the spec
  (grep `server.gen.go` for the path).
- `/aif-review` should check API-contract drift between `frontend/src/shared/api/types.ts`
  / feature `api.ts` and the OpenAPI spec.
