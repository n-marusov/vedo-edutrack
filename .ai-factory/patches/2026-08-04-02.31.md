# Phase and severity drift between ROADMAP.md and gates.yaml

**Date:** 2026-08-04 02:30
**Files:** deploy/ci/gates.yaml, deploy/ci/coverage-check.sh
**Severity:** medium

## Problem

`gates.yaml` had `current_phase: m0.2` and several delivery-tier gates at
`severity: advisory`, with comments like "blocking from M0.3". However, the
ROADMAP.md showed M0.3, M1, and M2 all marked as ✅ completed. This phase/severity
drift caused delivery gates (E2E GUI, E2E API, unit tests, integrations tests,
vitest) to always show as ⚠️ warn locally, masking real test status:

- `e2e-gui`: 5 BDD scenarios + scaffold smoke (40s runtime, failing)
- `e2e-api`: 7 contract tests (71s runtime, failing)
- Advisory severity folded all failures to warn, hiding the red status

Additionally, `coverage-check.sh` could not parse the Go coverage profile on
Windows, silently falling through with "could not parse" (also exit 0).

## Root Cause

1. **`current_phase`** was never updated after M0.3 completion (2026-08-03).
   The phase mechanism controls which gates are active; setting it to m0.2 when
   m0.3, m1, and m2 are completed meant the regression scope was stale.

2. **Gate severity** was set to `advisory` with intent to flip to `blocking`
   at M0.3, but the flip was never done. Comments in the YAML explicitly said
   "blocking from M0.3" but the field value stayed `advisory`.

3. **Go module path resolution** on Windows: `go tool cover -func` from outside
   the Go module directory cannot resolve import paths stored in the coverage
   profile, because it looks them up in GOPATH/GOROOT instead of the module
   workspace.

## Solution

1. **gates.yaml**: Changed `current_phase` from `m0.2` to `m0.3`. Changed
   severity for `go-test-unit`, `go-test-integration`, `e2e-gui`, `e2e-api`,
   and `vitest` from `advisory` to `blocking`. Updated deferred section comment
   from "never executed at m0.2" to "never executed at current_phase".

2. **coverage-check.sh**: Extracted `dirname` from the coverage file path and
   `cd` into it before invoking `go tool cover -func`, so the Go module is
   properly resolved on all platforms including Windows.

## Prevention

- After marking a milestone as ✅ completed in ROADMAP.md, always update
  `current_phase` in `deploy/ci/gates.yaml` to the next milestone phase.
- When a gate comment says "blocking from M<X>" and M<X> is completed, update
  the severity field immediately.
- Test Go tooling scripts (`go tool cover`, `go vet`) on both Unix and Windows
  — module path resolution differs (Unix is lenient, Windows is strict).
