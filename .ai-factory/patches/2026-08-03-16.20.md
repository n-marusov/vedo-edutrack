# Secrets-check gate false-positive on self-scanning + Playwright placeholder test + unused react-router dependency

**Date:** 2026-08-03 16:20
**Files:** deploy/ci/secrets-check.sh, tests/e2e/gui/tests/placeholder.spec.ts, frontend/package.json, pnpm-lock.yaml
**Severity:** medium

## Problem

`make gates` (delivery tier) exited 2 with one blocking failure and three failing areas:

1. **secrets-check (blocking/security) FAIL** — the gate reported private-key and hardcoded-credential hits, all pointing at its own source file `deploy/ci/secrets-check.sh` (lines 25–30 declare the `BEGIN … PRIVATE KEY` patterns; line 10 contains a `password=` comment).
2. **e2e-gui (advisory/test) FAIL** — Playwright browsers not installed locally (`chromium_headless_shell-1234` missing); after installing browsers, the placeholder test flipped to "Expected to fail, but passed" because the M0.3 frontend scaffold already serves the correct title.
3. **pnpm-audit (advisory/security) FAIL** — react-router `>=7.12.0 <8.3.0` high-severity advisory (RSC CSRF bypass, GHSA-qwww-vcr4-c8h2) pulled in via an unused `react-router-dom` dependency.

## Root Cause

- **Self-scanning:** a grep-based secret scanner that declares its match patterns inside its own source will always hit itself via `git grep`. The exclusion mechanism existed for other paths (`:!*.md`, `:!specs/` etc.) but not for the scanner's own file.
- **Scaffold readiness flip:** `test.fail(true)` (expected-to-fail) flips to a failure the moment the underlying assertion starts passing. The placeholder was written as a red scaffold for M0.3, but the scaffold was already in place — the guard became stale.
- **Dead dependency:** `react-router-dom@^7.0.0` was declared in `frontend/package.json` but never imported anywhere in the source, yet it still pulled the vulnerable `react-router` into the lockfile and tripped `pnpm audit`.

## Solution

1. `deploy/ci/secrets-check.sh` — added `SELF_EXCLUDE=':!deploy/ci/secrets-check.sh'` and passed it as a pathspec to all three `git grep` invocations (private keys, AWS, credentials). The gate now scans the repo while ignoring its own pattern declarations.
2. `tests/e2e/gui/tests/placeholder.spec.ts` — replaced the `test.fail(true, …)` placeholder with a real smoke test asserting the app title (`app scaffold renders with correct title`). Verified 3/3 browsers pass, 30 intentional M1–M10 stubs stay skipped.
3. `frontend/package.json` + root `pnpm-lock.yaml` — removed the unused `react-router-dom` dependency. `pnpm audit` now reports "No known vulnerabilities found".

## Prevention

- Secret scanners should exclude their own source file(s) from the scan (or keep pattern declarations in a data file that is never scanned).
- Before writing a "red scaffold" test with `test.fail(true)`, note the flip condition: once the asserted behavior is implemented, the test must be converted to a real assertion — otherwise it starts failing the suite.
- Run `pnpm audit` and remove unused dependencies as part of dependency hygiene; an unused package is both a supply-chain risk and dead weight.
- Locally, install Playwright browsers once (`pnpm exec playwright install chromium firefox webkit`) so the e2e-gui gate exercises the actual test logic instead of failing on a missing browser binary.
