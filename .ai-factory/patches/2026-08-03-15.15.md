# Corrupted allowBuilds placeholder text breaks frontend pnpm install / make build

**Date:** 2026-08-03 15:15
**Files:** frontend/pnpm-workspace.yaml
**Severity:** high (blocked `make build`)

## Problem

`make build` failed at the frontend step with:

```
[ERR_PNPM_IGNORED_BUILDS] Ignored build scripts: @biomejs/biome@1.9.4, esbuild@0.25.12
Run "pnpm approve-builds" to pick which dependencies should be allowed to run scripts.
[FAIL] build: backend=0 frontend=1
```

`pnpm build` in `frontend/` triggered pnpm's deps-status check which ran
`pnpm install`; that install errored because the build scripts of
`@biomejs/biome` and `esbuild` were considered not approved.

## Root Cause

`frontend/pnpm-workspace.yaml` (committed at HEAD) contained literal
placeholder text instead of boolean values:

```yaml
allowBuilds:
  '@biomejs/biome': set this to true or false
  esbuild: set this to true or false
```

`frontend/` is its own standalone pnpm workspace root (it has its own
`pnpm-workspace.yaml`, `pnpm-lock.yaml`, `node_modules/`, `.pnpm-store/`), so
running pnpm from `frontend/` reads THIS file, not the root
`pnpm-workspace.yaml`. The placeholder strings are not `true`, so pnpm treats
the builds as unapproved and fails the install.

The `frontend/.npmrc` workaround (`pnpm.onlyBuiltDependencies[]=...`) does not
help: pnpm 11.18 does not apply that .npmrc array syntax in a member
directory (`pnpm config get onlyBuiltDependencies` from `frontend` returns
`undefined`). The effective v11 mechanism is `allowBuilds: { <pkg>: true }`
in the workspace `pnpm-workspace.yaml`.

The placeholder text (`set this to true or false`) is pnpm's inline help text
for the `allowBuilds` config value — likely written into the YAML by a
misbehaving tool/agent instead of a real boolean.

## Solution

Replaced the placeholder strings with real booleans:

```yaml
allowBuilds:
  '@biomejs/biome': true
  esbuild: true
```

Verified: `cd frontend && pnpm install` runs both postinstall scripts and
`make build` passes (`backend binary + SPA build`).

## Prevention

- When configuring `allowBuilds` in `pnpm-workspace.yaml`, values MUST be
  YAML booleans (`true`/`false`), never the pnpm help placeholder text
  `set this to true or false`.
- If `pnpm config list` (or `pnpm config get allowBuilds`) shows the
  placeholder string as a value, the config file is corrupted — fix it.
- Regression gate: assert that neither `pnpm-workspace.yaml` contains the
  placeholder string, or run `cd frontend && pnpm install` as a build check.
- The root `.npmrc` comment claiming `allowBuilds` is deprecated in v11 is
  misleading — the empirical evidence is that `allowBuilds` with booleans in
  `pnpm-workspace.yaml` IS the working mechanism; `pnpm.onlyBuiltDependencies[]`
  in `.npmrc` is not applied from workspace member directories.
